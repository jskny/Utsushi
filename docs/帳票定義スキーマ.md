# 帳票定義スキーマ (`definition.json`)

対象コード: `src/Utsushi.ReportDefinition/ReportDefinitionJsonReader.cs`
対象要件: `.kiro/specs/excel-report-pdf-conversion/requirements.md` の要件2・要件6.3・要件8

帳票ごとの差異は、すべてこのファイルに閉じ込める。新しい帳票への対応は、共通レイヤーのコードを
変更せずにこのファイル(と `template.xlsx`・ゴールデンファイル)を追加するだけで完結する(要件8.1)。

## 配置

```
samples/reports/<帳票コード>/definition.json
samples/reports/<帳票コード>/template.xlsx
```

ディレクトリ名が帳票コードになる。`definition.json` の `reportCode` はディレクトリ名と一致していなければならず、
一致しない場合はロード時にエラーになる。

## 例

```json
{
  "schemaVersion": 1,
  "reportCode": "invoice",
  "sheetName": "請求書",
  "toleranceMm": 0.5,
  "unsupportedElements": "error",
  "maxDigitWidthPx": 7,
  "printArea": "A1:F34",
  "substitutionFields": [
    { "key": "CustomerName", "cell": "A3", "required": true,  "overflow": "shrink" },
    { "key": "InvoiceNo",    "cell": "F3", "required": true,  "overflow": "clip" },
    { "key": "Remarks",      "cell": "A29", "required": false, "overflow": "wrap" }
  ]
}
```

## プロパティ

| プロパティ | 型 | 必須 | 既定値 | 説明 |
|---|---|---|---|---|
| `schemaVersion` | 整数 | ✓ | — | スキーマのバージョン。現在の対応値は `1` のみ。 |
| `reportCode` | 文字列 | ✓ | — | 帳票コード。配置ディレクトリ名と一致させる。 |
| `sheetName` | 文字列 | ✓ | — | 変換対象のシート名。ブックに存在しない場合はエラー(要件1.4)。 |
| `substitutionFields` | 配列 | ✓ | — | 置換対象フィールドの一覧。空配列も可。 |
| `toleranceMm` | 数値 | — | `0.5` | Excel表示との許容誤差(mm)。0以上(要件4.5)。 |
| `unsupportedElements` | 文字列 | — | `"ignore"` | サポート外要素(対応済みプリセット以外の図形・接続線・グループ・グラフ・外部参照・デコード不能な画像形式)を検出したときの挙動。`ignore` / `error`(要件1.5, 9.4, 10.7)。PNG/JPEG/GIF/BMPの画像、および対応済みプリセットジオメトリの図形(矩形・角丸矩形・楕円・三角形・矢印6種・吹き出し3種)はこの設定によらず常に出力対象になる(要件9, 10)。 |
| `maxDigitWidthPx` | 数値 | — | `7` | 列幅換算に使う標準フォントの最大数字幅(96dpiのピクセル)。正の数。 |
| `printArea` | 文字列 | — | `null` | 印刷範囲の上書き(`"A1:F34"` 形式)。指定するとExcel側の印刷範囲設定より優先される。 |

### `substitutionFields[]` の要素

| プロパティ | 型 | 必須 | 既定値 | 説明 |
|---|---|---|---|---|
| `key` | 文字列 | ✓ | — | 置換キー(論理名)。定義内で一意。呼び出し元はセル番地ではなくこのキーで値を渡す。 |
| `cell` | 文字列 | ✓ | — | 置換先セル番地(A1形式)。結合セルの場合は範囲の**左上セル**を指定する。 |
| `required` | 真偽値 | — | `false` | `true` の場合、値が渡されない、または空文字・空白のみの値が渡されるとエラーになる(要件2.4, 2.12)。 |
| `overflow` | 文字列 | — | (未指定) | セル幅に収まらない場合の挙動(要件2.5)。下表を参照。省略した場合はExcel側のセル書式に従う。 |

### `overflow` の値

| 値 | 挙動 |
|---|---|
| `overflow` | はみ出しを許容し、隣接セルへ描画する(Excelの既定動作相当)。 |
| `shrink` | セル幅に収まるようフォントサイズを縮める(Excelの「縮小して全体を表示する」相当)。 |
| `clip` | セルの矩形で切り詰める。 |
| `wrap` | セル幅で折り返す。改行(LF/CRLF/CR)は段落区切りになる。折り返した行がセルの高さに収まらない場合はエラーになる(要件2.14。下記参照)。 |

折り返し(`wrap`、またはExcel側の`wrapText`)以外の挙動では、値に含まれる改行は表示されず1行につながる
(Excelと同じ。要件4.7)。住所などを複数行で表示したいセルは、テンプレート側で「折り返して全体を表示する」を
有効にするか、`overflow` に `wrap` を指定する。

差し込んだ値を折り返した結果、いずれかの行の半分以上がセルの外に出る場合は `LayoutComputationException` になる
(要件2.14)。Excelは行高を超えた行を黙って切り取り、縦位置が「下揃え」(既定)だと先頭の行から消えるため、
宛先住所の都道府県のような重要な部分が欠けたまま発行されるのを防ぐ。テンプレートの行の高さを、想定する
最大行数ぶん確保しておくこと。テンプレート自身に入力されている文字列は、従来どおりExcelと同じく切り取るだけとする。

`overflow` を指定しなかった置換対象セルには、Excel 側のセル書式が適用される
(`wrapText` が有効なら `wrap`、`shrinkToFit` が有効なら `shrink`、どちらでもなければ `overflow`)。
帳票定義で明示した場合は、そちらがセル書式より優先される。

つまり「テンプレート側の書式をそのまま使いたい」なら `overflow` を書かず、
「テンプレートの書式と違う挙動にしたい」ときだけ書く。

## `maxDigitWidthPx` について

Excel の列幅は「標準フォントで数字を何文字ぶん表示できるか」という単位で保存されており、
ポイントへ換算するには標準フォントの最大数字幅(MDW)が必要になる。

```
pixels = Truncate(((256 * width + Truncate(128 / MDW)) / 256) * MDW)
points = pixels * 72 / 96
```

MDW はフォントとサイズに依存するため、帳票定義側で指定できるようにしている。
標準的な 11pt のゴシック体では `7` でよい。帳票の列幅がExcel表示とずれる場合はこの値を見直す。

## 検証とエラー

ロード時に必須項目・型・値域・置換キーの重複を検証し、問題があれば
`ReportDefinitionSchemaException` を送出する(要件6.3)。例外には問題のあったプロパティのパス
(例: `substitutionFields[0].cell`)が含まれるため、どこが不正かを特定できる。

JSON Schema ライブラリは導入していない。スキーマが小さく固定的であり、依存を1つ減らせるため
(`.kiro/steering/tech.md`「依存ライブラリ追加時のルール」)。スキーマを変更する際は
`ReportDefinitionJsonReader` と本ドキュメントの両方を更新すること。
