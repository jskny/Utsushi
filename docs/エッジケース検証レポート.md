# エッジケース検証レポート(2026年10月)

対象読者: Utsushi を呼び出すプロダクトの開発者、帳票テンプレートを作る担当者、Utsushi の保守担当者。
関連: `samples/edge-cases/README.md`(サンプルの内容)、`docs/テンプレート作成ガイド.md`、`docs/ライブラリの使い方.md`

## 1. 目的と方法

手元の数点の Excel ではきちんと PDF 化できることを確認済みである。しかし実際の利用者がどんな Excel を作ってくるかは分からない。
そこで、帳票の担当者が普段の Excel 操作で作りがちなテンプレートを4点作り、極端な差し込み値と組み合わせて、
変換結果と利用者への影響を確かめた。

| 項目 | 内容 |
|---|---|
| サンプル | `samples/edge-cases/` の4帳票(送付状・売上一覧・工程表・注文書)。内容は `samples/edge-cases/README.md` |
| 差し込み値 | 標準的な値、長い値、必須の値だけ、空文字・空白のみ、外字・異体字・半角カナ・記号、改行・タブ・ゼロ幅スペース・BOM・壊れたサロゲート、絵文字、行数の多い住所、空白の無い長いURL、マイナスの金額など、約20通り |
| 確認方法 | (1) 自動テスト `tests/Utsushi.Golden.Tests/EdgeCaseSampleTests.cs`(31件、ページ構成・出力される文字列・例外の種類を検証)、(2) 生成した PDF を画像化して目視で確認、(3) 帳票定義なしの変換 |
| 環境 | Claude Code on the web(Linux)。游ゴシックが無いため `--allow-font-fallback`(同梱の BIZ UDPゴシックで代替)。外字は IPAmj明朝をインストールして確認 |

**この検証の限界**: テンプレートは Excel 実機ではなく openpyxl で生成している(数式のキャッシュ値などは Excel と同じ状態に補正済み)。
また Excel の印刷結果との突き合わせはしていない。下記の「Excel ではこう表示される」は Excel の仕様に基づく記述である。
游ゴシックの代わりに BIZ UDPゴシックで描いているため、文字幅が関係する見た目(収まる/はみ出す)は本番のフォントでは変わりうる。

## 2. 結論

- **変換が止まる・崩れて出力される、という致命的な不具合は見つからなかった。** 4帳票すべて、帳票定義あり・なしの両方で PDF になった。
- **差し込み値の不備は、黙って欠けた PDF を出さずに、原因の分かる例外で止まる。** 止まる値と、その理由は「4. 差し込み値の検証結果」の表のとおり。
  呼び出し側で値を整える処理(タブ・ゼロ幅スペースの除去など)を入れておくと、発行の失敗を減らせる。
- **印刷設定はよく再現されている。** 「すべての列を1ページに印刷」、見出し行・列の繰り返し、非表示の行・列、高さ0の行、
  行と列の手動改ページ、ページの方向、先頭ページ番号、先頭ページのみ別のヘッダー/フッターは、いずれも意図どおりに効いた。
- **一方で、利用者が普通に作るテンプレートで見た目が Excel と変わる箇所が5つあった**(「5. 利用者に影響する差異」)。
  特に「負の数を赤で表示する表示形式が黒で印字される」はドキュメントに記載が無く、帳票の担当者が気付きにくい。

## 4. 差し込み値の検証結果

例外で止まる値は、例外のメッセージに置換キーかセル番地(値の不備では文字の位置も)が入り、何を直せばよいかが分かる。

| 差し込み値 | 結果 | 呼び出し側での対策 |
|---|---|---|
| タブ文字を含む(Excel や表計算ソフトからのコピー&ペーストで混入しやすい) | `InvalidSubstitutionValueException` | タブを空白に置き換える |
| ゼロ幅スペース(U+200B)・BOM(U+FEFF)を含む(Web フォームやコピーで混入しやすい) | `InvalidSubstitutionValueException` | 除去する |
| 対になっていないサロゲート(文字列を途中で切ったときに生じる) | `InvalidSubstitutionValueException` | 文字数で切り詰めるときはサロゲートペアを分断しない |
| 必須の値が空文字・空白のみ・未指定 | `RequiredSubstitutionValueMissingException` | 入力側で必須チェックする |
| 帳票定義に無いキー(綴りの誤りなど) | `SubstitutionKeyNotFoundException` | — (開発時に気付ける) |
| 折り返すとセルの高さを超える住所(3行ぶんのセルに6行) | `LayoutComputationException`(セル A4) | 行数の上限を入力側で決めておく。テンプレートの行の高さを確保する |
| 絵文字(🙇) | `MissingGlyphException`(豆腐のまま出力しない) | 絵文字を除去する。氏名・住所の入力欄では受け付けない |
| 𠮷(JIS第4水準の外) | IPAmj明朝が無いと `MissingGlyphException`、あれば正常 | 外字を扱うサーバーには IPAmj明朝を入れる |

なお、次の値は**エラーにならず、見た目だけが変わる**。発行前のチェックでは検出されないため、テンプレートの作り方で防ぐ。

- 長い担当者名(はみ出し表示のセル): 右隣の「様」と重なる(「5. 利用者に影響する差異」の5-1)。
- 長い品名(結合セル・折り返しなし): 結合範囲の右端で切れる(Excel と同じ)。
- 長い部署名(`overflow: clip`): 右側が切れる。

## 5. 利用者に影響する差異

影響の大きい順に並べる。「記載」はテンプレート作成ガイド(`docs/テンプレート作成ガイド.md`)に書かれているかどうか。

| # | 差異 | 影響 | 記載 |
|---|---|---|---|
| 5-1 | 文字が隣のセルにはみ出すとき、隣のセルに値があっても止まらず重ねて描かれる | 高 | あり |
| 5-2 | 表示形式の色の指定(`[Red]` など)が反映されず、負の数が黒で印字される | 高 | **なし** |
| 5-3 | テンプレートに無いセルへの差し込みは、ブックの標準フォントではなく Calibri で描かれる | 中 | あり(Calibri 11pt になる) |
| 5-4 | 行全体・列全体に設定した書式が、空のセルに反映されない | 中 | あり |
| 5-5 | 差し込みセルがシートの「使用範囲」の外だとエラーになる(印刷範囲の中でも) | 低 | 一部あり |

### 5-1. はみ出した文字が隣の値と重なる

Excel は、はみ出し表示の文字を「隣の値のあるセルの手前」で止める。Utsushi は止めずに重ねて描く(設計書「未決事項」で既知)。
ガイドでは「はみ出す可能性があるセルは「縮小して全体を表示する」にする」としているが、**差し込みセルだけでなく、テンプレートに最初から入っている文字にも起きる**ため、
次のようなよくある作りで文字が重なる。

- 注文書: 狭い A 列の見出し「支払条件」が、右隣の B 列の「銀行振込」と重なる。「宛先の確認:」も右隣の値と重なる。
- 売上一覧: 得意先列の「合同会社見本ソリューションズ東日本支社」が、右隣の品目列の「保守サービス(年間)」と重なる。
- 送付状: 長い担当者名が、右隣の「様」と重なって「様」が読めなくなる。

一覧表の長い名称や、狭い列に入れた見出しは実帳票で非常に多い。Excel 上では正しく見えるため、担当者は PDF を見るまで気付けない。
**対応案**: Excel と同じく、隣の値のあるセルの手前で切り取る(要件4.9の拡張)。それまでの間は、ガイドのチェックリストに
「狭い列の見出し・一覧の長い名称は、縮小して全体を表示にするか列幅を広げる」を明記する。

### 5-2. 表示形式の色の指定が反映されない

日本語版 Excel の「数値」の書式で「負の数の表示形式」に赤を選ぶと `#,##0;[Red]-#,##0` のような表示形式になる。
注文書の値引き行(`-3,000`)は、Excel では赤字だが、PDF では黒字で印字された。組み込みの表示形式(通貨の6・8、数値の38・40)も同じ。

金額の帳票で「マイナスは赤」は一般的で、黒字で出ると読み手が正の値と誤読するおそれがある。
実装は意図的に色の指定を読み飛ばしている(`src/Utsushi.Parsing/OpenXml/NumericSection.cs`)が、要件・ガイドのどちらにも記載が無い。
**対応案**: 色の指定(`[Red]`・`[Blue]`・`[Color10]` など)を文字色として反映する。対応しない場合も、ガイドの「再現しない」に追記する。

### 5-3. テンプレートに無いセルへの差し込みは Calibri になる

一度も入力・書式設定をしていないセル(シートの使用範囲の中にあるもの。外にあるものは5-5)に差し込むと、Excel ならブックの標準フォント(日本語版の新規ブックでは游ゴシック)で表示されるが、
Utsushi は Calibri 11pt で描く(`src/Utsushi.Substitution/CellSubstitutor.cs`)。ガイドには「書式の無いセルは Calibri 11pt になる」と書かれているが、
次の2点はガイドから読み取りにくい。

- **既定の厳格モードでは、テンプレートで Calibri を一度も使っていないのに `FontNotAvailableException`(フォント 'Calibri')になる。**
  Calibri の無いサーバー(Linux コンテナなど)で起きる。標準フォントを IPAゴシックにしたブックで実際に確かめた。
- Calibri があるサーバーでも、日本語の部分は同梱の BIZ UDPゴシックで描かれ、Excel の見た目(游ゴシック)と変わる。

**対応案**: ブックの標準の書式(`cellXfs` の0番。`ReportModel.DefaultFont` として既に読み取っている)で描く。

### 5-4. 行全体・列全体の書式が空のセルに反映されない

行番号をクリックして行全体を塗りつぶすと、Excel はその行の空のセルもすべて塗りつぶして表示する(行の書式として保存される)。
Utsushi は値や書式を持つセルだけを描くため、塗りつぶしは文字のあるセルにしか出ない。列全体に設定した太字・文字色も、
送付状の C33(列全体の書式だけのセル)への差し込みには反映されなかった。ガイドには記載があるが、Excel の基本操作で起きるため踏みやすい。
**対応案**: 行・列の既定の書式(`row/@s`・`col/@style`)を読み取り、セルが無い位置にも適用する。

### 5-5. 使用範囲の外の差し込みセル

値も書式も無いセルが、シートの使用範囲(値か書式のあるセルを囲む範囲)の外にあると、そのセルを差し込み先にした場合、印刷範囲の中であっても
「置換キー 'V' の対象セル B2 が、シート 'S' の使用範囲 A1:A3の外にあります。」(`ReportStructureMismatchException`)になる。
ガイドの「値のないセルに差し込む場合も、先にセルへ書式を設定しておく」に従えば避けられるが、エラーメッセージの「使用範囲」が
テンプレートの担当者には分かりにくい。**対応案**: メッセージに「セルに書式(罫線・フォントなど)を設定してください」と対処を加える。

### その他(記載どおり、または影響が小さいもの)

ガイドに記載どおりの挙動だったもの: 縦書き・文字の回転(横書きになる)、均等割り付け(左揃え)、選択範囲内で中央(自セル内で中央)、
リッチテキスト(セル全体が1つの書式)、条件付き書式、網かけ(背景色の単色で近似)、グラデーションの塗りつぶし(透明)、
差し込みセルを参照する数式(再計算されず、テンプレート保存時の値が出る)、数値が収まらないときの `####`(表示されず数値がはみ出す)、
改ページをまたぐ結合セル、コメント(出力されない)、グラフ(以上は「5. 再現できるもの・できないもの」)。
表示形式が差し込んだ値に効かないこと(`@" 御中"` を設定したセルに差し込んでも「御中」が付かない)は「3. 差し込みセルの作り方」に記載がある。

ガイドに記載が無く、影響が小さいもの:

- 分数(`# ?/?`)・指数(`0.00E+00`)の表示形式は、標準の表示(`0.5`・`12345678`)になる(要件4.8の「解釈できない書式は標準」のとおり)。
- 網かけ(パターン)の近似に使う色は背景色のため、背景色が白だと濃い網かけでも消えて白になる(近似することは記載あり)。
- 入力規則(プルダウン)は出力されない(入力用の機能のため、印刷結果としては Excel と同じ)。

帳票定義なしでの変換で、フッターのファイル名(`&F`)に拡張子の無いファイル名が入ることは `docs/ライブラリの使い方.md` に記載がある。

## 6. プロダクト開発側(呼び出し側)への推奨事項

1. **差し込む前に値を整える**: タブ → 空白、ゼロ幅スペース・BOM の除去、絵文字の除去、サロゲートペアを分断しない切り詰め。
   これをしないと、コピー&ペーストされた住所などで発行が止まる(止まるのは安全側の動作である)。
2. **例外の種類ごとに対応を分ける**: 値の不備(`InvalidSubstitutionValueException`・`RequiredSubstitutionValueMissingException`・
   `MissingGlyphException`・差し込みセルの `LayoutComputationException`)は入力の修正を促し、それ以外はテンプレートや環境の問題としてログに残す。
3. **値の上限を入力画面で決める**: 住所の行数・宛名の文字数など、テンプレートの差し込みセルが収まる範囲を入力側でも制限する。
4. **フォント**: 本番のサーバーにテンプレートのフォントを入れる。外字を扱うなら IPAmj明朝も入れる(5-3 が直るまでは、テンプレートに無いセルへ差し込まない。Calibri は Microsoft のフォントで、Linux サーバーなどに自由に入れてよいものではない点に注意する)。

## 7. テンプレート作成ガイドへの追記候補

- 「再現しない」に、表示形式の色の指定(5-2)を追加する。
- 登録前のチェックリストに、「狭い列の見出し・一覧の長い名称が隣の値と重ならないか、PDF で確かめた」(5-1)と
  「行全体・列全体の塗りつぶし・書式を使っていない」(5-4)を追加する。

上記5-1〜5-5のライブラリ側の対応は、spec駆動開発の手順(要件・設計・タスクの更新)に沿って別途進める。
