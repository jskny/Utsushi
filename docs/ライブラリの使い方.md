# ライブラリの使い方 (`Utsushi`)

対象コード: `src/Utsushi/Excel2Pdf.cs`、`src/Utsushi/ReportPdfConverter.cs`
関連ドキュメント: `docs/テンプレート作成ガイド.md`(Excelテンプレートの作り方)、`docs/帳票定義スキーマ.md`(`definition.json` の書き方)、CLAUDE.md(開発コマンド)

呼び出し元プロダクトは `Utsushi` アセンブリ(`src/Utsushi/Utsushi.csproj`)が公開する
`Utsushi.Excel2Pdf`(セル番地を指定して書き換える簡易API)または `Utsushi.ReportPdfConverter`(値の辞書を渡すAPI)を
参照すればよい。`Excel2Pdf` は `ReportPdfConverter` の上に置いた薄い入口で、変換の処理・検証・例外は同じである。
`src/Utsushi.Cli` は `ReportPdfConverter` の薄いコマンドライン入口であり、実体はライブラリ側にある。

## 前提

- ターゲットフレームワークは `net5.0` 固定(`Directory.Build.props`。呼び出し元プロダクトが.NET 5のため)。
- NuGetパッケージとしての配布は行っていない。現状はソースツリー内から `Utsushi.csproj` への
  `ProjectReference` を前提とする。
- 主な変換対象は `samples/reports/<帳票コード>/` のように帳票定義を登録した自社帳票。任意のExcelファイルを
  汎用的に変換する用途ではない(CLAUDE.md「必ず守る制約」)。
- 帳票定義ありで変換する場合は、変換の前に対象帳票の `definition.json` と `template.xlsx` を用意しておく必要がある。
  書き方は `docs/帳票定義スキーマ.md` と `docs/テンプレート作成ガイド.md` を参照。
- 社内で作成したExcelファイルを帳票定義なしでPDF化することもできる(下記「帳票定義なしでの変換」)。
  ただし置換キーは使えずセル番地での書き換えのみで、見た目の一致を保証しないベストエフォートの変換である。

## 本番環境に導入する前に

| 準備 | 内容 |
|---|---|
| フォント | テンプレートで使うフォント(ＭＳ Ｐゴシック等)を、PDFを作るサーバーにインストールする。既定の厳格モードでは、無いフォントはエラーになる。BIZ UDPゴシックはライブラリに同梱しているため不要 |
| 外字 | 「𠮷」のようなJIS第4水準の外の人名用漢字を扱う場合は、IPAmj明朝をインストールする(下記「日本語の人名・住所の文字」) |
| 例外処理 | `UtsushiException` を捕捉し、`ToDiagnosticString()` をログに残す(下記「例外処理」)。差し込み値の不備(制御文字・空の必須値・行の高さに収まらない住所・字形の無い文字)も例外として送出されるため、発行を止めて呼び出し元で値を直す運用にする |
| 動作確認 | 想定する最長の値・最大行数の住所・外字を含む値で実際にPDFを作り、Excelの印刷プレビューと見比べる |
| ライセンス表記 | 同梱フォントのライセンス文(`Fonts/BIZUDPGothic-OFL.txt`。ビルド出力にコピーされる)を、配布物から削除しない |

## 簡易API `Excel2Pdf`(セル番地を指定して書き換える)

Excel ファイルを開き、セル番地を指定して値を書き込み、PDF として保存する書き方(要件14)。

```csharp
using System;
using Utsushi;

using var pdf = new Excel2Pdf("input.xlsx");     // 帳票定義なし(アクティブシートを変換)
pdf.SetText("C2", "Hello World");                // 文字列
pdf.SetValue("D5", 123.5);                       // 数値(double / decimal / long)
pdf.SetValue("F4", new DateTime(2026, 4, 1));    // 日時
pdf.Save("output.pdf");                          // 保存先のパス
```

帳票定義なしの変換(下記「帳票定義なしでの変換」)は、見た目の一致を保証しないベストエフォートの変換であり、
対応していない要素(グラフ・未対応の図形など)は黙って出力されない。社外に出す帳票は、帳票定義を登録して
「帳票定義を使う場合」の書き方で使うこと。

- `SetValue` で設定した数値・日時・時間は、**そのセルの表示形式**(通貨・桁区切り・日付・和暦・負の数の赤など)で表示される。
  Excel でセルに値を入力したのと同じ見た目になる。`SetText` で設定した文字列には表示形式は効かない
  (`SetText("C8", "1000")` は「1000」のまま。「¥1,000」と出したいセルは `SetValue("C8", 1000)` を使う)。
  横位置が「標準」のセルでは、数値は右、文字列は左に寄る。表示形式が「標準」のセルに日時を設定すると、シリアル値(例: 46113)のまま
  表示される(Excel のような表示形式の自動設定は行わない)ため、日付のセルにはテンプレートで日付の表示形式を設定しておく。
- 数値は Excel のセルと同じく `double` で扱う(`decimal` は有効数字15桁、`long` は 2^53 を超える部分が丸められる)。
  数値は折り返さず、セルの幅に収まらない場合も実際の値のまま描く(Excel の `####` にはしない)。大きな金額が入りうるセルは、
  保存の前に `CheckFit()` の `NumberTooWide` で確かめる。
- 同じセルに何度設定しても、最後に設定した値を使う(`"c2"`・`"$C$2"` のような表記の違いも同じセル)。
- 結合セルは、範囲の左上のセルの番地を指定する(それ以外の番地は保存の時点でエラー)。
- 呼び出しは続けて書ける(`pdf.SetText("A1", "x").SetValue("B1", 1);`)。
- 保存のたびに入力ファイルを読み直すため、値を変えて何度でも保存できる。`Save(Stream)` でストリームにも書き出せる。
  ファイルへの保存は、失敗時に不完全なPDFを残さない。
- `CheckFit()` で、設定した値が収まらない箇所を確認できる(下記「文字の収まりの確認」)。

| メソッド | 用途 | エラー |
|---|---|---|
| `SetText(cell, text)` | 文字列を設定する | セル番地がA1形式でない → `InvalidCellOverrideAddressException`(設定の時点)。制御文字などは保存の時点で `InvalidSubstitutionValueException` |
| `SetValue(cell, double/decimal/long)` | 数値を設定する | セル番地がA1形式でない → `InvalidCellOverrideAddressException`、NaN・無限大 → `InvalidSubstitutionValueException`(いずれも設定の時点) |
| `SetValue(cell, DateTime)` | 日時を設定する(Excel のシリアル値として。`DateTime.Kind` は考慮しない) | 1900年1月1日より前 → `InvalidSubstitutionValueException`(設定の時点) |
| `SetValue(cell, TimeSpan)` | 時間(時刻・経過時間)を設定する(日数をシリアル値として) | 負の時間 → `InvalidSubstitutionValueException`(設定の時点) |
| `SetField(key, text)` | 置換キーに値を設定する(帳票定義ありのときだけ) | 帳票定義なし → `InvalidOperationException` |
| `Save(path)` / `Save(stream)` | PDFを保存する | 変換の各段階の `UtsushiException`(下記「例外処理」) |
| `CheckFit()` | 文字の収まりを確認する | `Save` と同じ(PDFの描画の段階のエラーは除く) |

### 帳票定義を使う場合

登録済みの帳票(`definition.json`)を使う場合は、帳票コードと帳票定義のルートを渡す。置換キーは `SetField`、
帳票定義に無いセルは `SetText`/`SetValue` で書き換える。帳票定義の必須キー・`overflow`・`unsupportedElements` などが効く。

```csharp
using var pdf = new Excel2Pdf("samples/reports/invoice/template.xlsx", "invoice", "samples/reports");
pdf.SetField("CustomerName", "株式会社サンプル 御中")
   .SetField("InvoiceNo", "INV-0001")
   .SetField("TotalAmount", "¥1,000")
   .SetValue("F12", 320000);
pdf.Save("/tmp/invoice.pdf");
```

### 設定(`Excel2PdfOptions`)

| プロパティ | 内容 |
|---|---|
| `Fonts` | フォント解決の設定(`FontResolverOptions`)。省略時は厳格モード。開発環境での動作確認は `FontResolverOptions.AllowFallback()` |
| `Render` | PDF出力の設定(`PdfRenderOptions`) |
| `DocumentName` | 帳票定義なしの変換で、PDFのタイトル・`&F`・エラー情報に使う名前。省略時は入力ファイル名(拡張子なし) |
| `MaxDigitWidthPx` | 帳票定義なしの変換の最大数字幅(帳票定義ありでは指定できない) |

```csharp
using Utsushi.Rendering;   // FontResolverOptions

using var pdf = new Excel2Pdf("input.xlsx", new Excel2PdfOptions { Fonts = FontResolverOptions.AllowFallback() });
```

### 大量に発行する場合

`Excel2Pdf` を作るたびにフォントの解決をやり直さないよう、`ReportPdfConverter` を1つ作って渡す。
渡したコンバータは `Excel2Pdf` の `Dispose` では解放されないため、呼び出し元で `Dispose` する。
フォント・PDF出力の設定はコンバータのものを使う(`Excel2PdfOptions` の `Fonts`・`Render` を指定すると `ArgumentException`)。

```csharp
// 帳票定義なし
using var converter = ReportPdfConverter.CreateDefault();
foreach (var order in orders)
{
    using var pdf = new Excel2Pdf("template.xlsx", converter);
    pdf.SetText("B3", order.CustomerName).SetValue("F20", order.Total);
    pdf.Save(order.OutputPath);
}

// 帳票定義あり: 帳票定義のルートを指定してコンバータを作り、帳票コードを渡す(渡さないと帳票定義なしの変換になる)
using var reports = ReportPdfConverter.CreateDefault("samples/reports");
using var invoice = new Excel2Pdf("samples/reports/invoice/template.xlsx", reports, "invoice");
```

## 最小構成での利用(値の辞書を渡す書き方)

```csharp
using Utsushi;
using Utsushi.Rendering; // FontResolverOptions / PdfRenderOptions を使う場合に必要

// reportDefinitionRoot は definition.json / template.xlsx を配置したディレクトリの親
// (例: "samples/reports" 配下に "invoice/definition.json" がある)
using var converter = ReportPdfConverter.CreateDefault(reportDefinitionRoot: "samples/reports");

var values = new Dictionary<string, string>
{
    ["CustomerName"] = "株式会社サンプル 御中",
    ["InvoiceNo"] = "INV-0001",
    ["TotalAmount"] = "¥1,000",
};

converter.ConvertToFile(
    reportCode: "invoice",
    xlsxPath: "samples/reports/invoice/template.xlsx",
    values: values,
    outputPath: "/tmp/invoice.pdf");
```

`ReportPdfConverter` は内部で `FontResolver`(埋め込みフォントの解決に使うネイティブリソース)を
保持するため、`using` で確実に `Dispose` すること。

## 公開API

### `ReportPdfConverter.CreateDefault(reportDefinitionRoot, fontOptions?, renderOptions?)`

(帳票定義を使わない場合は `reportDefinitionRoot` を省いた `CreateDefault(fontOptions?, renderOptions?)` も使える。下記「帳票定義なしでの変換」。
両方のオーバーロードがあるため、`CreateDefault(null)` のように第1引数に `null` リテラルを渡すとコンパイルエラーになる)

既定構成(OpenXml解析 + SkiaSharp描画)でコンバータを組み立てる静的ファクトリ。

| 引数 | 型 | 説明 |
|---|---|---|
| `reportDefinitionRoot` | `string` | 帳票定義のルートディレクトリ。 |
| `fontOptions` | `FontResolverOptions?` | フォント解決の設定。省略時は厳格モード(`FontResolverOptions.Strict`)。 |
| `renderOptions` | `PdfRenderOptions?` | PDF出力の設定。省略時はフォント埋め込み(`PdfRenderOptions.Default`)。 |

各レイヤーの実装(`IWorkbookReader` 等)を個別に差し替えたい場合は、`ReportPdfConverter` の
コンストラクタに直接渡すこともできる(通常は `CreateDefault` で十分)。

### 変換メソッド

| メソッド | 戻り値 | 用途 |
|---|---|---|
| `Convert(reportCode, xlsxStream, values, output, cellOverrides?)` | `void` | Excelストリームを受け取り、PDFをストリームへ書き出す。 |
| `ConvertToFile(reportCode, xlsxPath, values, outputPath, cellOverrides?)` | `void` | ファイルパスで変換する。正常終了時のみ最終出力先を確定し、失敗時に不完全なPDFを残さない(要件5.4)。 |
| `ComputeLayout(reportCode, xlsxStream, values, cellOverrides?)` | `PagedLayout` | PDF描画の手前(Parsing→ReportDefinition→Substitution→Layout)までを実行する。描画結果ではなくページ構成そのものを検証したい場合に使う(ゴールデンテストでの利用が主だが、呼び出し元からも利用可能)。 |
| `CheckFit(reportCode, xlsxStream, values, cellOverrides?)` | `FitCheckResult` | PDFを出力せずに、文字がセルに収まらない箇所を返す(下記「文字の収まりの確認」)。 |

いずれも `reportCode` は `definition.json` の `reportCode`、`values` は置換キー(`substitutionFields[].key`)
→ 置換後の文字列の辞書。

### 帳票定義なしでの変換

帳票定義(`definition.json`)を用意していないExcelファイルは、次のメソッドでPDF化できる(要件12)。

| メソッド | 戻り値 | 用途 |
|---|---|---|
| `ConvertWithoutDefinition(xlsxStream, output, cellOverrides?, documentName?, maxDigitWidthPx?)` | `void` | ストリームで変換する。 |
| `ConvertFileWithoutDefinition(xlsxPath, outputPath, cellOverrides?, documentName?, maxDigitWidthPx?)` | `void` | ファイルパスで変換する。失敗時に不完全なPDFを残さない。 |
| `ComputeLayoutWithoutDefinition(xlsxStream, cellOverrides?, documentName?, maxDigitWidthPx?)` | `PagedLayout` | PDF描画の手前までを実行する。 |
| `CheckFitWithoutDefinition(xlsxStream, cellOverrides?, documentName?, maxDigitWidthPx?)` | `FitCheckResult` | PDFを出力せずに、文字がセルに収まらない箇所を返す(下記「文字の収まりの確認」)。 |

```csharp
// 帳票定義を使わないだけなら、帳票定義のルートは不要
using var converter = ReportPdfConverter.CreateDefault();
converter.ConvertFileWithoutDefinition("社内資料.xlsx", "/tmp/社内資料.pdf");
```

定義ありの変換との違い:

- 変換するのはブックのアクティブシート(Excelで保存したときに開いていたシート)1枚。それが非表示またはグラフシートなら、
  表示されている最初のワークシートを変換する。表示されているワークシートが無ければ `InvalidExcelFileException`。
- 置換キーによる差し込み(`values`)は使えない。セルの値を変えたい場合は `cellOverrides`(セル番地で直接上書き)を使う。
- 対応していない要素(グラフ・未対応の図形・EMF画像など)は、エラーにせず**黙って出力しない**
  (`unsupportedElements: "ignore"` 相当)。欠けていないかは出力したPDFを目で確かめること。
- 印刷範囲・改ページ・用紙設定はExcelの設定に従う。印刷範囲が無ければ、セルと画像・図形が置かれた範囲を印刷する。
- 列幅の換算に使う最大数字幅は、ブックの標準フォントから見積もる(Calibri 11pt=7、ＭＳ Ｐゴシック/游ゴシック 11pt=8、
  それ以外は7)。標準フォントを変えたブックで列幅がExcelとずれる場合は、`maxDigitWidthPx` 引数(CLI では
  `--max-digit-width`)で指定する。
- PDFのタイトル、ヘッダー/フッターのファイル名(`&F`/`&Z`。Excelと異なり拡張子は付かない)、例外の `ReportCode` には、帳票コードの代わりに
  文書名(`documentName`。省略時は、`ConvertFileWithoutDefinition` では拡張子を除いた入力ファイル名、ストリーム版では空文字列)が入る。
  ファイル名に取引先名などが含まれ、PDFのメタデータやログに出したくない場合は `documentName` を指定する。

社外に出す帳票など、見た目の一致を保証したい帳票は、帳票定義を登録して定義ありの変換を使うこと。

入力ファイルの規模(XMLの入れ子の深さ・パートの大きさ・列定義・改ページ・印刷範囲の個数・ページ数など)には
上限があり、超えるとエラーになる(要件6.6〜6.10。値は `.kiro/specs/excel-report-pdf-conversion/design.md`
「信頼できない入力に対する安全弁 一覧」)。ただし、不特定の外部ユーザーからアップロードされたファイルを
変換する公開サービスとしての利用は想定していない(`.kiro/steering/product.md`)。

`CreateDefault()`(引数なし、または `fontOptions`・`renderOptions` のみ)で作ったコンバータは帳票定義のルートを持たないため、
帳票コードを指定する `Convert` / `ConvertToFile` / `ComputeLayout` / `CheckFit` は `ReportDefinitionNotFoundException` になる。

### 文字の収まりの確認(`CheckFit`)

PDFを出力せずに、文字がセルの表示領域に収まらない箇所を返す(要件13)。PDF化の直前に呼び、結果を処理ログに残す用途を想定している。
変換の結果(PDF)は変わらない。Excel が `####` と表示する数値や、隣のセルの手前で切る文字も、PDFには実際の値のまま描かれる。

| メソッド | 戻り値 | 用途 |
|---|---|---|
| `CheckFit(reportCode, xlsxStream, values, cellOverrides?)` | `FitCheckResult` | 帳票定義ありの変換と同じ入力で確認する |
| `CheckFitWithoutDefinition(xlsxStream, cellOverrides?, documentName?, maxDigitWidthPx?)` | `FitCheckResult` | 帳票定義なしの変換と同じ入力で確認する |

`FitCheckResult` は、収まらない箇所の一覧 `Issues`(`IReadOnlyList<FitIssue>`)と、件数の上限(10,000件)で打ち切ったかどうか `IsTruncated` を持つ。

```csharp
using var input = File.OpenRead(xlsxPath);
var result = converter.CheckFit("invoice", input, values);
foreach (var issue in result.Issues)
{
    logger.Warn(issue.Message);   // 例: 「セル A5: 文字がセルからはみ出し、値のある隣のセル B5 に重なります…」
}

// 確認の後で変換する(ストリームは読み直す)
converter.ConvertToFile("invoice", xlsxPath, values, outputPath);
```

`FitIssue` のプロパティ:

| プロパティ | 内容 |
|---|---|
| `Kind` | 種類(下表) |
| `Cell` | セル番地(結合セルは範囲の左上) |
| `PageNumber` | そのセルが最初に現れるページの通し番号(1始まり)。ヘッダー/フッターの「先頭ページ番号」は反映しない。印刷タイトルのように複数ページに現れるセルも1件にまとめる |
| `Text` | 描画する文字列。宛名などの個人情報を含みうるため `Message` には入れていない。ログに残すかどうかは呼び出し元で決める |
| `IsSubstituted` / `SubstitutionKey` | 値を置き換えたセルかどうか / 置換キーで置き換えた場合はその置換キー(セル番地直接指定で上書きしたセルは null) |
| `Message` | ログに残すための説明の文(`ToString()` も同じ)。セル番地・置換キー・対処を含み、セルの文字列は含まない |

| `Kind` | 内容 | テンプレートでの対処 |
|---|---|---|
| `OverlapsNeighborValue` | はみ出した文字が、値のある隣のセルに重なる(Excel は隣のセルの手前で切る) | 列幅を広げるか、「縮小して全体を表示する」にする |
| `CutAtPageEdge` | はみ出した文字が、ページの端(余白の内側)で切れる | 同上 |
| `NumberTooWide` | 数値がセルの幅に収まらない(Excel は `####`、表示形式が標準なら桁を減らすか指数で表示する) | 列幅を広げる |
| `Clipped` | 切り取り表示(`overflow: clip`)、または結合セルの文字が、セル(結合範囲)の幅で切れる | 列幅・結合範囲を広げる。差し込む値の文字数を制限する |
| `ExceedsCellHeight` | テンプレートに入力してある文字を折り返すと、セルの高さに収まらない | 行の高さを広げる |

- 変換がレイアウトの計算までにエラーになる入力(必須の値が無い、差し込んだ住所が行の高さに収まらない など)では、変換と同じ例外を送出する。
  **PDFの描画で初めて分かるエラー(どのフォントにも字形の無い文字の `MissingGlyphException`)は送出しない**ため、確認の後の変換で起きうる。
- 縮小表示のセルは、文字を縮めて収めるため対象にしない。列幅がセル内の余白より狭いセルや、折り返さない文字が行の高さを超える縦方向のはみ出しも対象外。
- 文字の幅は描画と同じフォントで測る。PDFを作るサーバーと同じフォント構成で呼ぶこと(フォントが違えば結果も変わる)。
- 件数の上限は10,000件。超えた分は返さず、`IsTruncated` が true になる。
- `ComputeLayout` の戻り値の `PagedLayout.FitIssues` / `FitIssuesTruncated` も同じ内容である。PDFへの変換(`Convert` 等)は、この確認を行わない。

### 差し込む値の扱い

`values`・`cellOverrides` の値は、次の規則で扱われる(要件2.10〜2.14、4.6、4.7)。

| 渡し方 | 結果 |
|---|---|
| キーを渡さない(任意キー) | テンプレートに入力されている値がそのまま残る |
| 空文字 `""` | セルの値が消える(空欄になる)。必須キー(`required: true`)では `RequiredSubstitutionValueMissingException` |
| 空白のみ(`" "`・全角スペース) | 必須キーでは `RequiredSubstitutionValueMissingException`。任意キーではそのまま空白として出力(空でない値として扱うため、印刷範囲外の検出の対象にもなる) |
| `null` | `InvalidSubstitutionValueException`(空欄にしたい場合は空文字を渡す) |
| タブ等、改行以外の制御文字を含む | `InvalidSubstitutionValueException`(PDFで豆腐になるため。呼び出し元で除去・置換する) |
| ゼロ幅スペース(U+200B)・BOM(U+FEFF)等の不可視の書式文字を含む | `InvalidSubstitutionValueException`(Webや他システムからの貼り付けで混入しやすい) |
| 対になっていないサロゲートを含む | `InvalidSubstitutionValueException`(文字として描画できないため) |
| 改行(`\n`・`\r\n`・`\r`・U+2028・U+2029)を含む | `\n` に統一される。折り返し表示のセルでは改行として表示され、それ以外のセルでは改行は表示されず1行につながる(Excelの折り返し無効のセルに合わせた扱い) |
| 32,767文字(Excelのセルに入れられる文字数)を超える | `InvalidSubstitutionValueException`(`values`・`cellOverrides` とも) |

- `values`・`cellOverrides` の値は常に文字列としてセルへ入る(数値として入れてセルの表示形式で表示したい場合は
  `Excel2Pdf.SetValue` を使う)。テンプレートの数値書式・日付書式は適用されないため、
  金額(`"¥1,000"`)や日付(`"2026年4月1日"`)は呼び出し元で整形済みの文字列にして渡す。
  また横位置が「標準」のセルは文字列として左揃えになるため、金額欄は
  テンプレート側で横位置を「右揃え」にしておく。
- 住所などの複数行を入れるセルは、テンプレートで「折り返して全体を表示する」を有効にし、
  想定する最大行数ぶんの行の高さを確保しておく。差し込んだ値の折り返し行がセルに収まらないと、
  切り取られたまま発行されないよう `LayoutComputationException`(`CellAddress` にセル番地)になる。
- 空でない値を差し込んだセルが印刷範囲の外・非表示の行や列にある場合、または列幅・行の高さが無く表示できない場合は、
  値が出力されないため `LayoutComputationException` になる(必須キーは値の有無にかかわらず印刷範囲を検証される)。
- 必須キーのセルを `cellOverrides` で空文字・空白のみにすることはできない(`RequiredSubstitutionValueMissingException`)。
- セルのフォントに字形の無い文字(人名の外字「𠮷」など)は、外字用の代替フォントで描く
  (下記「日本語の人名・住所の文字」)。どのフォントにも無い文字(絵文字、IPAmj明朝の無いサーバーでの「𠮷」など)は、
  豆腐のまま出力せずに `MissingGlyphException` になる。その場合は、字形を持つフォントをサーバーに入れるか、
  呼び出し元で代替文字(「吉」など)に置き換える。

`cellOverrides` は省略可能な引数で、A1形式のセル番地 → 置換後の文字列の辞書。帳票定義
(`substitutionFields`)への登録有無に関わらず、指定したセルを直接上書きできる(要件2.7)。
結合セルは先頭(アンカー)セルの番地を指定する必要があり、それ以外を指定すると
`NonAnchorMergedCellOverrideException` になる(下記「例外処理」参照)。
`"B1"`・`"b1"`・`"$B$1"` のように表記が違っても同じセルを指す番地を同時に渡すと、どちらの値を使うか決められないため
`InvalidCellOverrideAddressException` になる。列名はASCIIの英字(`A`〜`Z`・`a`〜`z`)だけを受け付ける(全角の`Ａ１`などは不可)。
1回の変換で渡せる `cellOverrides` は10,000件まで(`Excel2Pdf` の `SetText`・`SetValue` は合わせて10,000セルまで。
超えると `InvalidSubstitutionValueException`。`Target` は `"cellOverrides"`)。

```csharp
converter.ConvertToFile(
    reportCode: "invoice",
    xlsxPath: "samples/reports/invoice/template.xlsx",
    values: values,
    outputPath: "/tmp/invoice.pdf",
    cellOverrides: new Dictionary<string, string> { ["A1"] = "請求書(控)" });
```

### 例外処理

変換の失敗時は必ず `Utsushi.Core.Exceptions.UtsushiException` の派生例外を送出する(要件6.4)。
`Stage` プロパティでどのレイヤーで失敗したかを判別でき、`ReportCode` / `SheetName` / `CellAddress`
に判明している範囲の情報が入る。人が読める形式は `ToDiagnosticString()` で得られる。

ただし、呼び出し側のプログラムの誤りである引数の不正は、`UtsushiException` ではなく .NET の標準の引数例外になる(要件6.14)。
入力ファイルの読み込みやレイアウト計算を始める前にすべての引数を検証するため、時間のかかる処理の後で引数の誤りが分かることはない。

| 引数の不正 | 例外 |
|---|---|
| `reportCode`・`xlsxStream`・`xlsxPath`・`values`・`output`・`outputPath` が `null` | `ArgumentNullException` |
| `outputPath` が空文字・空白のみ | `ArgumentException` |
| `maxDigitWidthPx` が0以下・NaN・無限大 | `ArgumentOutOfRangeException` |
| `Excel2Pdf`: 入力ファイルのパスが空白のみ、帳票コードが空白のみ、帳票定義ありで `MaxDigitWidthPx` を指定、コンバータを渡して `Fonts`・`Render` を指定 | `ArgumentException` |
| `Excel2Pdf`: 帳票定義なしで `SetField` を呼んだ | `InvalidOperationException` |
| `Excel2Pdf`: `Dispose` の後に使った | `ObjectDisposedException` |

出力先のパスの形式が不正(NUL文字を含むなど)な場合や、出力先に書き込めない場合は、引数例外ではなく `PdfRenderingException` になる(下表)。

```csharp
using Utsushi.Core.Exceptions;

try
{
    converter.ConvertToFile(reportCode, xlsxPath, values, outputPath);
}
catch (UtsushiException ex)
{
    // ex.Stage: Parsing / ReportDefinition / Substitution / Layout / Rendering
    Console.Error.WriteLine(ex.ToDiagnosticString());
}
```

主な派生例外(すべて `src/Utsushi.Core/Exceptions/` に定義):

| 例外 | 段階 | 追加情報 | 主な発生条件 |
|---|---|---|---|
| `InvalidExcelFileException` | Parsing | `Reason`(`NotOpenXmlFormat` 等) | 破損ファイル・非xlsx・パスワード保護 |
| `UnsupportedWorkbookElementException` | Parsing | `ElementKind` | 図形・外部参照等、サポート外要素かつ `unsupportedElements: "error"` |
| `ReportDefinitionNotFoundException` | ReportDefinition | — | `reportCode` に対応する `definition.json` が無い |
| `ReportDefinitionSchemaException` | ReportDefinition | `DefinitionPath` / `PropertyPath` | `definition.json` のスキーマ違反(別々の置換キーが同じセルを指す場合を含む) |
| `ReportStructureMismatchException` | ReportDefinition | — | シート名・セル番地がExcelと定義で不一致。置換キーの対象セルが使用範囲(値か書式のあるセルの範囲)の外にある |
| `SubstitutionKeyNotFoundException` | Substitution | `Key` | `values` に定義されていないキーがある |
| `RequiredSubstitutionValueMissingException` | Substitution | `Key` | `required: true` のキーが `values` に無い、または値が空文字・空白のみ |
| `InvalidSubstitutionValueException` | Substitution | `Target` | 値が `null`、または改行以外の制御文字・不可視の書式文字(ゼロ幅スペース等)・対になっていないサロゲートを含む。値が32,767文字を超える。`cellOverrides`(`Excel2Pdf` では文字列・数値の合計)が10,000件を超える(`Target` は `"cellOverrides"`)。`Excel2Pdf.SetValue` の数値が NaN・無限大、日時が1900年より前、時間が負 |
| `InvalidCellOverrideAddressException` | Substitution | `Address` | `cellOverrides` のキーがA1形式のセル番地として解釈できない。表記の異なる複数のキー(`"B1"` と `"$B$1"` など)が同じセルを指す |
| `NonAnchorMergedCellOverrideException` | Substitution | `AnchorAddress` | `cellOverrides` が結合セル範囲内の先頭(アンカー)以外を指定している |
| `LayoutComputationException` | Layout | `CellAddress`(差し込みセルの検証の場合) | ページ分割・座標計算の失敗、差し込み値のセルが印刷範囲外(印刷タイトルの行・列でも、どのページにもタイトルとして付かない場合を含む)・非表示の行や列・幅や高さが0の行や列にある、折り返した差し込み値がセルの高さに収まらない、行全体・列全体の書式で描くセルの無い位置が上限(200,000か所)を超える |
| `PdfRenderingException` | Rendering | `InnerException`(出力の失敗の場合) | PDF描画の失敗。出力先へ書き込めない場合(出力先のパスが不正、出力先ディレクトリを作れない、ディスクの空き不足・ネットワーク切断など書き込み中の入出力エラー)も、元の例外(`IOException`・`UnauthorizedAccessException` 等)を `InnerException` に入れてこの例外になる |
| `FontNotAvailableException` | Layout / Rendering | `FontName` | 厳格モードでフォントが解決できない(下記)。レイアウト計算中の文字幅の計測で起きた場合は `Stage` が `Layout`、PDFの描画中なら `Rendering` になり、どちらも `ReportCode`・`SheetName` が入る |
| `MissingGlyphException` | Rendering | `FontName` / `CodePoint` / `Text` | 描画する文字(異体字を含む)の字形が、セルのフォントにも外字用の代替フォントにも無い(下記) |

`ConvertToFile`・`ConvertFileWithoutDefinition` は、出力先と同じディレクトリに一時ファイル(`<出力先>.<GUID>.utsushi-tmp`)を
書いてから出力先へ置き換える。失敗時は一時ファイルを削除し、不完全なPDFは残らない(要件5.4)。ただし、プロセスの強制終了や
電源断のように後始末が動かない異常終了では一時ファイルが残ることがある。出力先のディレクトリに `*.utsushi-tmp` が残っていたら、
変換中のプロセスが無いことを確かめてから削除してよい。

### フォント解決 (`FontResolverOptions`)

対象帳票が使うフォントが実行環境に無い場合、既定(厳格モード)では `FontNotAvailableException` になる。

```csharp
// 厳格モード(既定)。フォントが無ければ例外。
var strict = FontResolverOptions.Strict;

// 代替フォントを許容する(見た目は崩れる可能性がある)。開発環境での動作確認向け。
// 代替フォント名を省略すると同梱のBIZ UDPゴシックで代替する(日本語フォントの無い環境でも日本語を描ける)。
var fallback = FontResolverOptions.AllowFallback();
var fallbackIpa = FontResolverOptions.AllowFallback("IPAGothic");

// サーバーにインストールせず、フォントファイルを直接登録する(Linuxサーバーで Windows のフォントを使う場合など)。
// 英語名で登録しても、日本語版Excelのフォント名「ＭＳ Ｐゴシック」から引ける。
// .ttc(複数の書体を含むファイル)は、キーのファミリ名と一致する書体を中から選ぶ
// (msgothic.ttc なら MS Gothic / MS UI Gothic / MS PGothic のうち MS PGothic)。
var registered = FontResolverOptions.Strict with
{
    FontFiles = new Dictionary<string, string> { ["MS PGothic"] = "/opt/fonts/msgothic.ttc" },
};
```

`FontResolverOptions` は `Mode`(`FontResolutionMode.Strict` / `AllowFallback`)のほか、
`FontFiles`(ファミリ名→フォントファイルパスの明示指定。`ファミリ名:bold` 等で太字の実字形も登録できる)、
`FontDirectories`(一括登録ディレクトリ)、`FallbackFamilyName`(代替フォント名)、
`GlyphFallbackFamilies`(外字用の代替フォント。下記)を持つレコード型。フォントのライセンス上、
サーバーで使ってよいフォントかどうかは導入前に確認すること。本番運用では厳格モードのまま対象フォントを確実にインストールし、
`AllowFallback` は開発環境での動作確認用と位置づける(CLAUDE.md「開発コマンド」も参照)。
`FontResolver` を直接使い、`RegisterFontFile`・`RegisterFontDirectory` で後からフォントを登録した場合も、
それより前に解決済みのフォント名(代替フォントで解決したものを含む)に登録が反映される。

### 日本語の人名・住所の文字(外字・異体字)

宛名・住所の文字は、次の仕組みで豆腐や別の字に化けないようにしている(要件11)。

| 項目 | 挙動 |
|---|---|
| 同梱フォント | BIZ UDPゴシック(JIS第1〜第4水準、IVSの一部。SIL OFL 1.1)をライブラリに同梱している。`AllowFallback()` の代替先(代替フォント名の省略時)はこのフォント。日本語フォントの無いサーバー・CIでも日本語を描画できる。セル書式で「BIZ UDPゴシック」を指定すれば厳格モードでもそのまま使える |
| 外字 | セルのフォントに字形が無い文字は、`GlyphFallbackFamilies`(既定: BIZ UDPゴシック → IPAmj明朝)の順に、字形を持つフォントでその文字だけを描く。送り幅もレイアウト計算に反映される |
| 異体字 | 「葛」+ U+E0100 のような異体字セレクタ(IVS/SVS)付きの文字は、その異体字を登録しているフォントの字形で描く。どのフォントにも登録が無ければ `MissingGlyphException`(基底文字で黙って代用しない) |
| 濁点 | 「か」+ U+3099(合成用濁点)は「が」の字形で描く。CJK互換漢字(「﨑」U+FA11 など)は正規化せず、渡されたコードポイントの字形で描く |
| フォント名 | 「ＭＳ Ｐゴシック」「游ゴシック」のような日本語のフォント名は、英語名(「MS PGothic」「Yu Gothic」)のフォントとしても探す |

「𠮷」(U+20BB7)のようなJIS第4水準の外の人名用漢字は同梱フォントに無い。これらを含む帳票を発行するサーバーには
**IPAmj明朝**(文字情報基盤のMJ文字、約6万字・IVS対応、IPAフォントライセンス)をインストールする。インストールされて
いれば既定で外字用に使う(Debian/Ubuntu は `apt-get install fonts-ipamj-mincho`、Windows は文字情報技術促進協議会の
配布ページから入手してインストールする)。IPAmj明朝は46MBあるが、PDFには使った字形だけを埋め込むため数KBしか増えない。
IPAmj明朝は明朝体のみのため、ゴシック体の宛名の中で外字だけが明朝体になる点に注意する。

社内で作成した外字フォント(私用領域 U+E000〜U+F8FF に字形を持つTrueTypeフォント。Windowsの EUDC.TTE など)を使う場合は、
フォントファイルを登録し、外字用の代替フォントに加える(EUDC.TTE も中身はTrueType形式だが、
Windowsの外字ファイルでの動作は開発環境では確認できていない。導入時に実ファイルで確認すること)。

```csharp
var fontOptions = FontResolverOptions.Strict with
{
    FontFiles = new Dictionary<string, string> { ["社内外字"] = @"C:\Fonts\EUDC.TTE" },
    GlyphFallbackFamilies = new[] { "社内外字", "BIZ UDPGothic", "IPAmjMincho" },
};
using var converter = ReportPdfConverter.CreateDefault("reports", fontOptions);
```

文字単位の代替は厳格モード(`FontResolverOptions.Strict`)でも行う。厳格モードが例外にするのは「セルのフォント自体が
見つからない」場合である。英字フォント(Arial・Calibri 等)のセルに日本語を入れた場合も、日本語の部分は
BIZ UDPゴシックで描かれる。Excel はこの場合ブックの東アジア用フォント(例: ＭＳ Ｐゴシック)を使うため、文字幅が違い、
折り返し位置などが変わりうる。日本語を入れるセルには、テンプレート側で日本語フォントを指定しておく。

`GlyphFallbackFamilies` を空にすると文字単位の代替を行わない(セルのフォントに字形の無い文字は `MissingGlyphException`)。
見つからないフォント名は飛ばす(IPAmj明朝の無い環境でも、既定の一覧のままでエラーにはならない)。

PDFから文字列をコピー・検索した場合、異体字の字形は基底文字(例「葛」)として取り出される(異体字セレクタは含まれない)。

### PDF出力オプション (`PdfRenderOptions`)

```csharp
// 既定: フォントを埋め込む(使った字形だけのサブセット)。PDF内の文字列検索・コピーが可能。
var withSearch = PdfRenderOptions.Default;

// 文字をアウトライン化する。見た目は同一で大幅に小さくなるが、PDF内検索・コピー・テキスト抽出は不可。
var compact = PdfRenderOptions.OutlineText;
```

`PdfRenderOptions` は `Title` / `Creator` / `Producer` / `RasterDpi` / `EncodingQuality` /
`TextRendering`(`PdfTextRendering.EmbedFont` / `Outline`)/ `MissingGlyphs` を持つレコード型。

`MissingGlyphs` は、セルのフォントにも外字用の代替フォントにも字形の無い文字を描画しようとしたときの扱い(要件5.5)。既定の
`MissingGlyphPolicy.Error` では、豆腐(□)や空白のままPDFを出力せず `MissingGlyphException` になる。
例外の `Text` に、その文字を含む描画文字列(1行分)が入る。代替フォントでの見た目確認など、
開発用途で欠落を許容したい場合だけ `MissingGlyphPolicy.Render` を指定する。例外メッセージには
描画文字列の先頭10文字だけが入る(宛名・住所がログに丸ごと出ないようにするため)。


```csharp
// 開発環境での動作確認用: 字形が無い文字があっても出力する(豆腐になる)
var lenient = PdfRenderOptions.Default with { MissingGlyphs = MissingGlyphPolicy.Render };
```

フォントは、帳票で使った字形だけを含むサブセットにして埋め込む(要件11.5。請求書サンプルで約54KB)。
CFF形式のフォント(Noto Sans CJK など)・可変フォント・埋め込み許可が制限されたフォントはサブセット化せず、
SkiaSharp が Type 3(字形の輪郭をそのまま収める形式。文字列検索がしにくく、異体字の文字列抽出も欠ける)または
フォント全体の埋め込みで出力する。帳票・外字用のフォントには TrueType 形式のもの(.ttf/.ttc。MSゴシック、
游ゴシック、BIZ UD、IPA系など)を使う。形式は拡張子では判別できない(.ttc にも CFF 形式のものがある)。

## 複数スレッドからの利用

1つの `ReportPdfConverter` を複数スレッドから同時に使ってよい(変換ごとの状態は呼び出し単位で作られ、
共有するのはフォントとフォントの計量値のキャッシュ、プロセス内で共有する数値書式の解析結果のキャッシュ、
読み取り・検証済みの画像のバイト列の表(画像パートごと。パッケージと一緒に回収される)だけで、いずれもスレッド安全にしている)。大量発行する場合も、
コンバータは1つ作って使い回し、アプリケーション終了時に `Dispose` する。

なお現状、変換のたびに `definition.json` と `.xlsx` の全体を読み直す(解析結果のキャッシュは無い)。
開発環境の実測では、請求書サンプル1件あたり約0.1秒・約60KBだった。

## `Utsushi.Core` の共通型

利用者が直接触れる可能性のある値型・列挙型(`src/Utsushi.Core/`):

| 型 | 内容 |
|---|---|
| `CellAddress` | A1形式のセル番地。`Parse` / `TryParse` を持つ readonly struct。 |
| `CellRange` | セル範囲(A1形式)。`Parse` / `TryParse` / `Contains` を持つ readonly struct。 |
| `ArgbColor` | ARGB色。`Black` / `White` / `Transparent` 静的プロパティ、`TryParseHex`。 |
| `PointPt` / `RectPt` | ポイント単位の座標・矩形(原点は左上、Y軸下方向)。 |
| `Units` | pt / mm / px / EMU の換算ユーティリティ。内部座標系はすべてポイントに統一している。 |
| `ProcessingStage` | `UtsushiException.Stage` が取る値(`Parsing` / `ReportDefinition` / `Substitution` / `Layout` / `Rendering` 等)。 |

## CLIでの利用例(参考実装)

`src/Utsushi.Cli/Program.cs` はこのライブラリの呼び出し例そのものであり、実装の参考になる。

```bash
dotnet run --project src/Utsushi.Cli -- \
  --report invoice --input samples/reports/invoice/template.xlsx \
  --output /tmp/invoice.pdf --definitions samples/reports \
  --set CustomerName="株式会社サンプル 御中" --set InvoiceNo="INV-0001" --set TotalAmount="¥1,000" \
  --override A1="請求書(控)"

# 帳票定義なしで変換する(--report を省略する。--set・--definitions は使えない)
dotnet run --project src/Utsushi.Cli -- \
  --input samples/reports/invoice/template.xlsx --output /tmp/no-definition.pdf
```

(開発環境にテンプレートのフォントが無い場合は、どちらの例にも `--allow-font-fallback` を付ける。CLAUDE.md「開発コマンド」参照)

`--allow-font-fallback [フォント名]` は `FontResolverOptions.AllowFallback` に(フォント名を省略すると同梱のBIZ UDPゴシック)、
`--outline-text` は `PdfRenderOptions.OutlineText` に、
`--allow-missing-glyphs` は `MissingGlyphs = MissingGlyphPolicy.Render` に、
`--override <セル番地>=<値>` は `cellOverrides` に対応する。

終了コードは、成功が `0`、使い方の誤りが `2`、変換の失敗(`UtsushiException`、入力ファイルの読み書きの失敗)が `3`。
次の場合は変換を行わず使い方エラー(`2`)になる(要件6.15)。

- `--set`・`--override` に同じキーを重ねて指定した(後の値で黙って上書きしない)。キーは大文字・小文字を区別して比べるため、
  `--override B1=…` と `--override b1=…` はここでは重複にならず、ライブラリ側で `InvalidCellOverrideAddressException`(終了コード `3`)になる
- `--definitions` の値が空
- 入力ファイル・帳票定義ルートのパスが不正(NUL文字を含むなど)。出力先のパスが不正な場合は `PdfRenderingException` で終了コード `3` になる
