# ライブラリの使い方 (`Utsushi`)

対象コード: `src/Utsushi/Excel2Pdf.cs`、`src/Utsushi/Excel2PdfEngine.cs`、`src/Utsushi/Excel2PdfDiagnostics.cs`
関連ドキュメント: `docs/テンプレート作成ガイド.md`(Excelテンプレートの作り方)、CLAUDE.md(開発コマンド)

呼び出し元プロダクトは `Utsushi` アセンブリ(`src/Utsushi/Utsushi.csproj`)が公開する `Utsushi.Excel2Pdf` を使う。
Excel ファイルを開き、セル番地を指定して値を書き込み、PDF として保存する。大量に発行する場合・サーバーで使う場合は、
フォントの解決を使い回すための `Utsushi.Excel2PdfEngine` を1つ作って渡す。
`src/Utsushi.Cli` は `Excel2Pdf` の薄いコマンドライン入口(`check`・`convert`)であり、実体はライブラリ側にある。

## 前提

- ターゲットフレームワークは `net5.0` 固定(`Directory.Build.props`。呼び出し元プロダクトが.NET 5のため)。
- NuGetパッケージとしての配布は行っていない。現状はソースツリー内から `Utsushi.csproj` への
  `ProjectReference` を前提とする。
- 対象は社内で作成・管理している帳票テンプレート。任意のExcelファイルを汎用的に変換する用途ではない(CLAUDE.md「必ず守る制約」)。
  テンプレートの作り方は `docs/テンプレート作成ガイド.md` を参照。

## 本番環境に導入する前に

| 準備 | 内容 |
|---|---|
| テンプレートの診断 | 使うテンプレートを CLI の `check`(または `Excel2Pdf.Check()`)で診断し、未対応の要素・文字の収まらない箇所・フォントの代替が無いことを確かめる(下記「診断」)。未対応の要素があると、既定では保存がエラーになる |
| フォント | テンプレートで使うフォント(ＭＳ Ｐゴシック等)を、PDFを作るサーバーにインストールする。既定の厳格モードでは、無いフォントはエラーになる。BIZ UDPゴシックはライブラリに同梱しているため不要 |
| 外字 | 「𠮷」のようなJIS第4水準の外の人名用漢字を扱う場合は、IPAmj明朝をインストールする(下記「日本語の人名・住所の文字」) |
| 例外処理 | `UtsushiException` を捕捉し、`ToDiagnosticString()` をログに残す(下記「例外処理」)。書き込む値の不備(制御文字・行の高さに収まらない住所・字形の無い文字)も例外として送出されるため、発行を止めて呼び出し元で値を直す運用にする |
| 動作確認 | 想定する最長の値・最大行数の住所・外字を含む値で実際にPDFを作り、Excelの印刷プレビューと見比べる |
| スレッド | サーバー(ASP.NET Core など)では `Excel2PdfEngine` を1つ作って共有し、`Excel2Pdf` はリクエストごとに作る(下記「複数スレッドからの利用」) |
| ライセンス表記 | 同梱フォントのライセンス文(`Fonts/BIZUDPGothic-OFL.txt`。ビルド出力にコピーされる)を、配布物から削除しない |

## `Excel2Pdf`(セル番地を指定して書き込む)

```csharp
using System;
using Utsushi;

using var pdf = new Excel2Pdf("input.xlsx");     // アクティブシートを変換する
pdf.SetText("C2", "Hello World");                // 文字列
pdf.SetValue("D5", 123.5);                       // 数値(double / decimal / long)
pdf.SetValue("F4", new DateTime(2026, 4, 1));    // 日時
pdf.Save("output.pdf");                          // 保存先のパス
```

- `SetValue` で設定した数値・日時・時間は、**そのセルの表示形式**(通貨・桁区切り・日付・和暦・負の数の赤など)で表示される。
  Excel でセルに値を入力したのと同じ見た目になる。`SetText` で設定した文字列には表示形式は効かない
  (`SetText("C8", "1000")` は「1000」のまま。「¥1,000」と出したいセルは `SetValue("C8", 1000)` を使う)。
  横位置が「標準」のセルでは、数値は右、文字列は左に寄る。表示形式が「標準」のセルに日時を設定すると、シリアル値(例: 46113)のまま
  表示される(Excel のような表示形式の自動設定は行わない)ため、日付のセルにはテンプレートで日付の表示形式を設定しておく。
- 数値は Excel のセルと同じく `double` で扱う(`decimal` は有効数字15桁、`long` は 2^53 を超える部分が丸められる)。
  数値は折り返さず、セルの幅に収まらない場合も実際の値のまま描く(Excel の `####` にはしない。「折り返して全体を表示する」の
  セルではセルの幅で切れ、それ以外のセルでははみ出す)。大きな金額が入りうるセルは、保存の前に `Check()` の `NumberTooWide` で確かめる。
- 書き込んだ文字がセルに収まらない場合の扱いは、**セルの書式**で決まる。「縮小して全体を表示する」なら縮小、
  「折り返して全体を表示する」なら折り返し(行の高さに収まらなければエラー)、どちらも無ければはみ出し表示(結合セルは結合範囲で切る)。
- 同じセルに何度設定しても、最後に設定した値を使う(`"c2"`・`"$C$2"` のような表記の違いも同じセル)。
- 結合セルは、範囲の左上のセルの番地を指定する(それ以外の番地は保存の時点でエラー)。
- 呼び出しは続けて書ける(`pdf.SetText("A1", "x").SetValue("B1", 1);`)。
- 1つの `Excel2Pdf` を複数スレッドから同時に使わない。サーバーではリクエストごとに作る(下記「複数スレッドからの利用」)。
- 保存のたびに入力ファイルを読み直すため、値を変えて何度でも保存できる。`Save(Stream)` でストリームにも書き出せる。
  ファイルへの保存は、失敗時に不完全なPDFを残さない。

| メソッド | 用途 | エラー |
|---|---|---|
| `SetText(cell, text)` | 文字列を設定する | セル番地がA1形式でない → `InvalidCellOverrideAddressException`(設定の時点)。制御文字などは保存の時点で `InvalidSubstitutionValueException` |
| `SetValue(cell, double/decimal/long)` | 数値を設定する | セル番地がA1形式でない → `InvalidCellOverrideAddressException`、NaN・無限大 → `InvalidSubstitutionValueException`(いずれも設定の時点) |
| `SetValue(cell, DateTime)` | 日時を設定する(Excel のシリアル値として。`DateTime.Kind` は考慮しない) | 1900年1月1日より前 → `InvalidSubstitutionValueException`(設定の時点) |
| `SetValue(cell, TimeSpan)` | 時間(時刻・経過時間)を設定する(日数をシリアル値として) | 負の時間 → `InvalidSubstitutionValueException`(設定の時点) |
| `Save(path)` / `Save(stream)` | PDFを保存する | 未対応要素があれば `UnsupportedWorkbookElementException`(既定。下記「未対応要素」)。そのほか変換の各段階の `UtsushiException`(下記「例外処理」) |
| `ToPdfBytes()` | PDFをバイト列で返す(Webのレスポンス・データベースへの保存など) | `Save` と同じ |
| `Clear()` / `Clear(cell)` | すべての設定 / 1セルの設定を消す。以降はテンプレートの値になる | `Clear(cell)` のセル番地がA1形式でない → `InvalidCellOverrideAddressException` |
| `Check()` | PDFを出力せずに、表示が崩れる原因を一覧で返す(下記「診断」) | 未対応要素では例外にしない。それ以外は `Save` と同じ(PDFの描画の段階のエラーは除く) |

### 変換するシート

- 変換するのはブックのアクティブシート(Excelで保存したときに開いていたシート)1枚。それが非表示またはグラフシートなら、
  表示されている最初のワークシートを変換する。表示されているワークシートが無ければ `InvalidExcelFileException`。
  `Excel2PdfOptions.SheetName` で名前を指定すれば、そのシート(非表示のシートを含む)を変換する。
- 印刷範囲・改ページ・用紙設定はExcelの設定に従う。印刷範囲が無ければ、セルと画像・図形が置かれた範囲を印刷する。
- 列幅の換算に使う最大数字幅は、ブックの標準フォントから見積もる(Calibri 11pt=7、ＭＳ Ｐゴシック/游ゴシック 11pt=8、
  それ以外は7)。標準フォントを変えたブックで列幅がExcelとずれる場合は、`MaxDigitWidthPx`(CLI では `--max-digit-width`)で指定する。
- PDFのタイトル、ヘッダー/フッターのファイル名(`&F`/`&Z`。Excelと異なり拡張子は付かない)、例外の `DocumentName` には文書名が入る
  (`Excel2PdfOptions.DocumentName`。省略時は、パスで作った場合は拡張子を除いた入力ファイル名、バイト列・ストリームで作った場合は空文字列)。
  ファイル名に取引先名などが含まれ、PDFのメタデータやログに出したくない場合は `DocumentName` を指定する。

入力ファイルの規模(XMLの入れ子の深さ・パートの大きさ・列定義・改ページ・印刷範囲の個数・ページ数など)には
上限があり、超えるとエラーになる(値は `.kiro/specs/excel-report-pdf-conversion/design.md`「信頼できない入力に対する安全弁 一覧」)。
ただし、不特定の外部ユーザーからアップロードされたファイルを変換する公開サービスとしての利用は想定していない(`.kiro/steering/product.md`)。

### ファイル以外の入出力

テンプレートをデータベースや埋め込みリソースに置く場合は、パスの代わりにバイト列またはストリームを渡す。
内容は作成の時点で写して保持するため、後で配列を書き換えたりストリームを閉じたりしても影響しない(ストリームは読み終えるが、閉じるのは呼び出し元)。
内容の上限は100MB(超えると `InvalidExcelFileException`、`Reason=TooLarge`。パスで渡す場合は読み込みの安全弁の上限(1GB)が効くため、
上限が異なる)。シークできるストリームは、読み始める前に残りの長さで上限を確かめる。内容はインスタンスが破棄されるまで保持する。
読めないストリームは `ArgumentException`、読み取りの失敗は `InvalidExcelFileException`。
文書名(`DocumentName`)を省略すると空文字列になり、エラー情報の文書名も空になるため、指定することを勧める。

```csharp
byte[] template = LoadTemplateFromDatabase();
using var pdf = new Excel2Pdf(template, new Excel2PdfOptions { DocumentName = "請求書" });
pdf.SetText("C2", "Hello World");
byte[] pdfBytes = pdf.ToPdfBytes();
```

### 1つのインスタンスを使い回す場合

宛先ごとに値を設定して保存する場合は、前の宛先の値が残らないよう、保存のたびに `Clear()` で設定を消す。

```csharp
using var pdf = new Excel2Pdf("template.xlsx");
foreach (var customer in customers)
{
    pdf.Clear()
       .SetText("B3", customer.Name)
       .SetValue("F20", customer.Total);
    pdf.Save(customer.OutputPath);
}
```

### 設定(`Excel2PdfOptions`)

| プロパティ | 内容 |
|---|---|
| `Fonts` | フォント解決の設定(`FontResolverOptions`)。省略時は厳格モード。開発環境での動作確認は `FontResolverOptions.AllowFallback()`。エンジンを渡す場合は指定できない |
| `Render` | PDF出力の設定(`PdfRenderOptions`)。エンジンを渡す場合は指定できない |
| `DocumentName` | 文書名。PDFのタイトル・`&F`・エラー情報に使う。省略時は、パスで作った場合は入力ファイル名(拡張子なし)、バイト列・ストリームで作った場合は空文字列 |
| `MaxDigitWidthPx` | 列幅の換算に使う最大数字幅(ピクセル)。省略時はブックの標準フォントから見積もる |
| `SheetName` | 変換するシートの名前(大文字・小文字を区別する)。省略時はアクティブシート。非表示のシートも名前で指定すれば変換する。ブックに無い、またはグラフシートなどワークシートでない場合は保存の時点で `InvalidExcelFileException`(`Reason=NoWorksheet`) |
| `UnsupportedElements` | 未対応要素の扱い。既定は `UnsupportedElementPolicy.Error`(下記「未対応要素」)。欠落を承知で変換する場合は `Ignore` |

```csharp
using Utsushi.Rendering;   // FontResolverOptions

using var pdf = new Excel2Pdf("input.xlsx", new Excel2PdfOptions { Fonts = FontResolverOptions.AllowFallback() });
```

### 大量に発行する場合(`Excel2PdfEngine`)

`Excel2Pdf` を作るたびにフォントの解決をやり直さないよう、`Excel2PdfEngine` を1つ作って渡す。
渡したエンジンは `Excel2Pdf` の `Dispose` では解放されないため、呼び出し元で `Dispose` する。
フォント・PDF出力の設定はエンジンのものを使う(`Excel2PdfOptions` の `Fonts`・`Render` を指定すると `ArgumentException`)。
破棄したエンジンを渡すと、作成の時点で `ObjectDisposedException` になる。

```csharp
using var engine = Excel2PdfEngine.Create(fonts: null, render: null);   // 既定: フォントは厳格モード
foreach (var order in orders)
{
    using var pdf = new Excel2Pdf("template.xlsx", engine);
    pdf.SetText("B3", order.CustomerName).SetValue("F20", order.Total);
    pdf.Save(order.OutputPath);
}
```

## 未対応要素(PDFに出力されない要素)

グラフ・対応していない図形・EMFなど描けない形式の画像・コメントやフォームコントロール(レガシー図形)・外部リンクなど、
PDFに出力されない要素を「未対応要素」と呼ぶ。既定(`UnsupportedElementPolicy.Error`)では、保存(`Save`・`ToPdfBytes`)の時点で
`UnsupportedWorkbookElementException` になる。最初の1件で止めず、ブック全体で見つかった要素をすべて持つ。

| プロパティ | 内容 |
|---|---|
| `Elements` | 見つかった未対応要素(`UnsupportedElement`)の一覧。件数は10,000件まで |
| `IsTruncated` | 件数の上限で打ち切った場合は true |
| `Message` | 先頭20件の要素を1行ずつ含む。`ToDiagnosticString()` は先頭100件を含み、100件を超えた場合は種類ごとの件数を加える |

`UnsupportedElement` は、種類(`Kind`)・シート名(`SheetName`)・アンカーのセル番地(`Anchor`。分かる場合)・補足の情報(`Detail`。
図形のプリセット名・画像の形式など)・説明の文(`Message`)を持つ。`ToString()` は1行の説明(例: `[Chart] シート '注文書' C32: グラフは出力されません。`)。
ファイル由来の文字列(シート名・補足の情報)は、制御文字を除いて64文字で切り詰める。

| `Kind` | 内容 |
|---|---|
| `Chart` | グラフ |
| `UnsupportedDrawingObject` | 対応していない描画オブジェクト(SmartArt・インク・3Dモデルなど) |
| `UnsupportedAnchor` | 位置の指定の形式に対応していない描画オブジェクト(絶対位置のアンカーなど) |
| `UnsupportedShapePreset` | 対応していない図形のプリセット(`Detail` にプリセット名) |
| `UnsupportedGroupChild` | グループの中の、描けない要素 |
| `UnsupportedImageFormat` | 描けない形式の画像(EMF・WMF など。`Detail` に形式) |
| `MissingImagePart` | 画像の本体が見つからない |
| `LimitExceeded` | 図形・画像の数などの上限を超えたため、超えた分を読み飛ばした |
| `ExternalReference` | 外部の画像・リンクへの参照 |
| `LegacyDrawing` | コメント・フォームコントロールなどのレガシー図形 |
| `MalformedDrawingObject` | 位置・大きさの情報が欠けているか壊れている描画オブジェクト |
| `HeaderFooterImage` | ヘッダー/フッターの画像 |

欠落を承知で変換する場合は `UnsupportedElements = UnsupportedElementPolicy.Ignore` を指定する。その要素を除いてPDFを出力する。

```csharp
using var pdf = new Excel2Pdf("order.xlsx", new Excel2PdfOptions { UnsupportedElements = UnsupportedElementPolicy.Ignore });
```

## 診断(`Check()`)

PDFを出力せずに、表示が崩れる原因を一覧で返す。設定した値で確かめる。テンプレートを登録する前・直した後や、
PDF化の直前に呼んで結果を処理ログに残す用途を想定している。変換の結果(PDF)は変わらない。

```csharp
using var pdf = new Excel2Pdf(xlsxPath);
pdf.SetText("A3", customerName).SetValue("C8", total);

var diagnostics = pdf.Check();
foreach (var element in diagnostics.UnsupportedElements) { logger.Error(element.ToString()); }
foreach (var issue in diagnostics.FitIssues) { logger.Warn(issue.Message); }
foreach (var font in diagnostics.FontSubstitutions) { logger.Warn("フォントの代替: " + font); }
foreach (var approximation in diagnostics.FormatApproximations) { logger.Info(approximation.ToString()); }

if (!diagnostics.HasIssues)
{
    pdf.Save(outputPath);
}
```

`Excel2PdfDiagnostics` のプロパティ:

| プロパティ | 内容 |
|---|---|
| `UnsupportedElements` / `UnsupportedElementsTruncated` | 未対応要素(上記)。未対応要素の扱いがエラーでも、例外にせずに一覧で返す |
| `FitIssues` / `FitIssuesTruncated` | 文字がセルに収まらない箇所(下記「文字の収まり」)。10,000件まで |
| `FontSubstitutions` | フォントの代替(下記) |
| `FormatApproximations` / `FormatApproximationsTruncated` | 書式の近似(下記)。参考情報。種類ごとに1,000件まで |
| `HasIssues` | 未対応要素・文字の収まらない箇所・フォントの代替のいずれかがあるかどうか。書式の近似は含めない |
| `HasFormatApproximations` | 書式の近似があるかどうか |

- `Check()` のエラーは、未対応要素の扱いを無視にした場合の `Save` と同じ(未対応要素を理由に例外にしない)。
  変換がレイアウトの計算までにエラーになる入力(書き込んだ住所が行の高さに収まらない など)では、保存と同じ例外を送出する。
  **PDFの描画で初めて分かるエラー(どのフォントにも字形の無い文字の `MissingGlyphException`)は送出しない**ため、診断の後の保存で起きうる。
- 文字の幅とフォントの代替は描画と同じフォントの構成で求める。PDFを作るサーバーと同じ環境で呼ぶこと。

### フォントの代替

テンプレートが指定したフォントが無く、代替の書体で描く場合に1件になる(`FontSubstitution`: `RequestedFamily`・`Bold`・`Italic`・
`ActualFamily`。`ToString()` は「ＭＳ Ｐゴシック(太字) → BIZ UDPGothic」)。フォントの代替を許可した設定(`FontResolverOptions.AllowFallback`)でだけ起きる
(厳格モードでは、無いフォントは `FontNotAvailableException`)。外字の補い(セルのフォントに無い文字だけを別のフォントで描くこと)は含めない。

### 書式の近似(参考)

PDFには出力されるが、Excelと見た目が異なりうる書式。エラーにはしない(`HasIssues` にも含めない)。
`FormatApproximation` は、種類(`Kind`)・シート名・位置(`Location`。セル範囲)・補足の情報(`Detail`。`"horizontal=distributed"` のように
ファイルの値の表記)・説明の文(`Message`)を持つ。印刷される範囲(印刷範囲・印刷タイトル。非表示の行・列を除く)にあるものだけを返す。

| `Kind` | 内容(Utsushi の描き方) |
|---|---|
| `TextRotation` | 文字の回転・縦書き(回転せずに横書きで描く) |
| `HorizontalAlignment` | 横位置の均等割り付け・両端揃え・繰り返し(左揃え)、選択範囲内で中央(セル内の中央揃え) |
| `VerticalAlignment` | 縦位置の両端揃え・均等割り付け(中央揃え) |
| `Indent` | 右揃え・中央揃えのインデント(Excelと位置がずれうる) |
| `ConditionalFormatting` | 条件付き書式(条件によらず元の書式で描く) |
| `RichText` | 一部の文字の書式が異なるセル(セル全体をセルの書式で描く) |
| `NumberFormat` | 解釈できない表示形式(分数・指数など)と、表示形式で表せない値(負の経過時間・明治より前の日付の和暦)。標準の表示形式で表示する |
| `CellFillPattern` / `CellFillGradient` | セルの網かけ(背景色の単色)・グラデーション(塗りつぶしなし) |
| `ShapeFill` | 図形のグラデーション・模様・画像の塗りつぶし(単色で描くか塗りつぶさない) |
| `ShapeFont` | 図形の文字のスタイル・テーマが指す書体、日本語の文字の東アジアの書体の欠落(既定の書体・英数字の書体で描く) |
| `ImageFlip` / `ImageRotation` | 画像の反転(反転せずに描く)、45度以上135度未満(225度以上315度未満)の回転(位置・大きさがずれうる) |
| `MultiLineHeaderFooter` | 複数行のヘッダー/フッター(1行で描く) |
| `MergedCellAcrossPageBreak` | 改ページをまたぐ結合セル(両方のページに同じ文字を描く) |
| `DrawingAcrossPageBreak` | 改ページをまたぐ画像・図形(左上が属するページにだけ描く) |
| `MergedCellHiddenEdge` | 最後の行・列が非表示で、その下端・右端に罫線がある結合セル(その罫線を描かない) |

### 文字の収まり

Excel が `####` と表示する数値や、隣のセルの手前で切る文字も、PDFには実際の値のまま描かれる。そうした箇所を `FitIssue` で返す。

| プロパティ | 内容 |
|---|---|
| `Kind` | 種類(下表) |
| `Cell` | セル番地(結合セルは範囲の左上) |
| `PageNumber` | そのセルが最初に現れるページの通し番号(1始まり)。ヘッダー/フッターの「先頭ページ番号」は反映しない。印刷タイトルのように複数ページに現れるセルも1件にまとめる |
| `Text` | 描画する文字列。宛名などの個人情報を含みうるため `Message` には入れていない。ログに残すかどうかは呼び出し元で決める |
| `IsSubstituted` | 呼び出し元が値を書き込んだ(`SetText`・`SetValue`)セルかどうか |
| `Message` | ログに残すための説明の文(`ToString()` も同じ)。セル番地・対処を含み、セルの文字列は含まない |

| `Kind` | 内容 | テンプレートでの対処 |
|---|---|---|
| `OverlapsNeighborValue` | はみ出した文字が、値のある隣のセルに重なる(Excel は隣のセルの手前で切る) | 列幅を広げるか、「縮小して全体を表示する」にする |
| `CutAtPageEdge` | はみ出した文字が、ページの端(余白の内側)で切れる | 同上 |
| `NumberTooWide` | 数値がセルの幅に収まらない(Excel は `####`、表示形式が標準なら桁を減らすか指数で表示する) | 列幅を広げる |
| `Clipped` | 結合セルの文字が、結合範囲の幅で切れる(結合セルの文字ははみ出さない) | 列幅・結合範囲を広げる。書き込む値の文字数を制限する |
| `ExceedsCellHeight` | テンプレートに入力してある文字を折り返すと、セルの高さに収まらない | 行の高さを広げる |

- 縮小表示のセルは、文字を縮めて収めるため対象にしない。列幅がセル内の余白より狭いセルや、折り返さない文字が行の高さを超える縦方向のはみ出しも対象外。
- 保存(`Save`)は、この確認を行わない。

## 書き込む値の扱い

`SetText` の値は、次の規則で扱われる(要件2.10〜2.16、4.6、4.7)。

| 値 | 結果 |
|---|---|
| 空文字 `""` | セルの値が消える(空欄になる) |
| 空白のみ(`" "`・全角スペース) | そのまま空白として出力(空でない値として扱うため、印刷範囲外の検出の対象にもなる) |
| `null` | `ArgumentNullException`(設定の時点) |
| タブ等、改行以外の制御文字を含む | `InvalidSubstitutionValueException`(PDFで豆腐になるため。呼び出し元で除去・置換する) |
| ゼロ幅スペース(U+200B)・BOM(U+FEFF)等の不可視の書式文字を含む | `InvalidSubstitutionValueException`(Webや他システムからの貼り付けで混入しやすい) |
| 対になっていないサロゲートを含む | `InvalidSubstitutionValueException`(文字として描画できないため) |
| 改行(`\n`・`\r\n`・`\r`・U+2028・U+2029)を含む | `\n` に統一される。折り返し表示のセルでは改行として表示され、それ以外のセルでは改行は表示されず1行につながる(Excelの折り返し無効のセルに合わせた扱い) |
| 32,767文字(Excelのセルに入れられる文字数)を超える | `InvalidSubstitutionValueException` |

- 住所などの複数行を入れるセルは、テンプレートで「折り返して全体を表示する」を有効にし、
  想定する最大行数ぶんの行の高さを確保しておく。書き込んだ値の折り返し行がセルに収まらないと、
  切り取られたまま発行されないよう `LayoutComputationException`(`CellAddress` にセル番地)になる。
- 空でない値を書き込んだセルが印刷範囲の外・非表示の行や列にある場合、または列幅・行の高さが無く表示できない場合は、
  値が出力されないため `LayoutComputationException` になる。
- セルのフォントに字形の無い文字(人名の外字「𠮷」など)は、外字用の代替フォントで描く
  (下記「日本語の人名・住所の文字」)。どのフォントにも無い文字(絵文字、IPAmj明朝の無いサーバーでの「𠮷」など)は、
  豆腐のまま出力せずに `MissingGlyphException` になる。その場合は、字形を持つフォントをサーバーに入れるか、
  呼び出し元で代替文字(「吉」など)に置き換える。
- 結合セルは先頭(アンカー)セルの番地を指定する必要があり、それ以外を指定すると保存の時点で
  `NonAnchorMergedCellOverrideException` になる。列名はASCIIの英字(`A`〜`Z`・`a`〜`z`)だけを受け付ける(全角の`Ａ１`などは不可)。
  1つの `Excel2Pdf` で設定できるセルは、`SetText`・`SetValue` を合わせて10,000セルまで(超えると保存の時点で
  `InvalidSubstitutionValueException`。`Target` は `"cellOverrides"`)。

## 例外処理

変換の失敗時は必ず `Utsushi.Core.Exceptions.UtsushiException` の派生例外を送出する(要件6.4)。
`Stage` プロパティでどのレイヤーで失敗したかを判別でき、`DocumentName` / `SheetName` / `CellAddress`
に判明している範囲の情報が入る。人が読める形式は `ToDiagnosticString()` で得られる(文書名は `document=` の見出しで出る。文書名・シート名の制御文字は取り除く)。
`InnerException.Message` はファイル由来の不正な値(改行を含みうる)をそのまま含むことがあるため、ログに残す場合は呼び出し元で改行を取り除くか長さを制限する。
`Excel2PdfOptions` の `SheetName`(Excel のシート名の規則に合わない名前)・`DocumentName`(制御文字・書式文字・行区切りを含むか255文字を超える)は、作る時点で `ArgumentException` になる。

ただし、呼び出し側のプログラムの誤りである引数の不正は、`UtsushiException` ではなく .NET の標準の引数例外になる(要件6.14)。
入力ファイルの読み込みやレイアウト計算を始める前にすべての引数を検証するため、時間のかかる処理の後で引数の誤りが分かることはない。

| 引数の不正 | 例外 |
|---|---|
| 入力のパス・バイト列・ストリーム、保存先のパス・ストリーム、`SetText` の文字列、エンジンが `null` | `ArgumentNullException` |
| 入力のパス・保存先のパスが空文字・空白のみ、`SheetName` が空白のみまたは Excel のシート名の規則に合わない、`DocumentName` が制御文字・書式文字・行区切りを含むか255文字を超える、エンジンを渡して `Fonts`・`Render` を指定 | `ArgumentException` |
| `MaxDigitWidthPx` が0以下・NaN・無限大 | `ArgumentOutOfRangeException` |
| `Excel2Pdf`・破棄したエンジンを、`Dispose` の後に使った | `ObjectDisposedException` |

出力先のパスの形式が不正(NUL文字を含むなど)な場合や、出力先に書き込めない場合は、引数例外ではなく `PdfRenderingException` になる(下表)。

```csharp
using Utsushi.Core.Exceptions;

try
{
    pdf.Save(outputPath);
}
catch (UtsushiException ex)
{
    // ex.Stage: Parsing / Substitution / Layout / Rendering
    Console.Error.WriteLine(ex.ToDiagnosticString());
}
```

主な派生例外(すべて `src/Utsushi.Core/Exceptions/` に定義):

| 例外 | 段階 | 追加情報 | 主な発生条件 |
|---|---|---|---|
| `InvalidExcelFileException` | Parsing | `Reason`(`NotOpenXmlFormat` 等) | 破損ファイル・非xlsx・パスワード保護・入力ファイルが無い・シートが無い |
| `UnsupportedWorkbookElementException` | Parsing | `Elements` / `IsTruncated` | 未対応要素があり、未対応要素の扱いがエラー(既定) |
| `InvalidSubstitutionValueException` | Substitution | `Target` | 値に改行以外の制御文字・不可視の書式文字(ゼロ幅スペース等)・対になっていないサロゲートを含む。値が32,767文字を超える。設定したセルが10,000を超える(`Target` は `"cellOverrides"`)。`SetValue` の数値が NaN・無限大、日時が1900年より前、時間が負 |
| `InvalidCellOverrideAddressException` | Substitution | `Address` | セル番地がA1形式のセル番地として解釈できない |
| `NonAnchorMergedCellOverrideException` | Substitution | `AnchorAddress` | 結合セル範囲内の先頭(アンカー)以外のセルに書き込んだ |
| `LayoutComputationException` | Layout | `CellAddress`(書き込んだセルの検証の場合) | ページ分割・座標計算の失敗、書き込んだセルが印刷範囲外(印刷タイトルの行・列でも、どのページにもタイトルとして付かない場合を含む)・非表示の行や列・幅や高さが0の行や列にある、折り返した値がセルの高さに収まらない、行全体・列全体の書式で描くセルの無い位置が上限(200,000か所)を超える |
| `PdfRenderingException` | Rendering | `InnerException`(出力の失敗の場合) | PDF描画の失敗。出力先へ書き込めない場合(出力先のパスが不正、出力先ディレクトリを作れない、ディスクの空き不足・ネットワーク切断など書き込み中の入出力エラー)も、元の例外(`IOException`・`UnauthorizedAccessException` 等)を `InnerException` に入れてこの例外になる |
| `FontNotAvailableException` | Layout / Rendering | `FontName` | 厳格モードでフォントが解決できない(下記)。レイアウト計算中の文字幅の計測で起きた場合は `Stage` が `Layout`、PDFの描画中なら `Rendering` になり、どちらも `DocumentName`・`SheetName` が入る。フォントの代替を許す設定で、指定した代替フォント名が見つからない場合も、`Excel2Pdf`・`Excel2PdfEngine.Create` を作る時点でこの例外になる(`Stage` は `Rendering`、文書名・シート名は入らない) |
| `MissingGlyphException` | Rendering | `FontName` / `CodePoint` / `Text` | 描画する文字(異体字を含む)の字形が、セルのフォントにも外字用の代替フォントにも無い(下記) |

ファイルへの保存(`Save(path)`)は、出力先と同じディレクトリに一時ファイル(`<出力先>.<GUID>.utsushi-tmp`)を
書いてから出力先へ置き換える。失敗時は一時ファイルを削除し、不完全なPDFは残らない(要件5.4)。ただし、プロセスの強制終了や
電源断のように後始末が動かない異常終了では一時ファイルが残ることがある。出力先のディレクトリに `*.utsushi-tmp` が残っていたら、
変換中のプロセスが無いことを確かめてから削除してよい。

### フォント解決 (`FontResolverOptions`)

対象帳票が使うフォントが実行環境に無い場合、既定(厳格モード)では `FontNotAvailableException` になる。

```csharp
// 厳格モード(既定)。フォントが無ければ例外。
var strict = FontResolverOptions.Strict;

// 代替フォントを許容する(見た目は崩れる可能性がある)。開発環境での動作確認向け。
// 代替フォント名を省略すると同梱のBIZ UDPゴシックで代替する(日本語フォントの無い環境でも日本語を描ける)。
var fallback = FontResolverOptions.AllowFallback();
var fallbackIpa = FontResolverOptions.AllowFallback("IPAGothic");   // 指定した書体が無ければ、作る時点で FontNotAvailableException

// サーバーにインストールせず、フォントファイルを直接登録する(Linuxサーバーで Windows のフォントを使う場合など)。
// 英語名で登録しても、日本語版Excelのフォント名「ＭＳ Ｐゴシック」から引ける。
// .ttc(複数の書体を含むファイル)は、キーのファミリ名と一致する書体を中から選ぶ
// (msgothic.ttc なら MS Gothic / MS UI Gothic / MS PGothic のうち MS PGothic)。
var registered = FontResolverOptions.Strict with
{
    FontFiles = new Dictionary<string, string> { ["MS PGothic"] = "/opt/fonts/msgothic.ttc" },
};
```

`FontResolverOptions` は `Mode`(`FontResolutionMode.Strict` / `AllowFallback`)のほか、
`FontFiles`(ファミリ名→フォントファイルパスの明示指定。`ファミリ名:bold` 等で太字の実字形も登録できる)、
`FontDirectories`(一括登録ディレクトリ)、`FallbackFamilyName`(代替フォント名)、
`GlyphFallbackFamilies`(外字用の代替フォント。下記)を持つレコード型。代替フォント名を指定して、その書体が明示登録・インストール済み・同梱のいずれにも無い場合は、同梱フォントで黙って代替せず、
`FontResolver`(`Excel2Pdf`・`Excel2PdfEngine`)を作る時点で `FontNotAvailableException` になる(書体名の誤りに気付けるようにするため)。フォントのライセンス上、
サーバーで使ってよいフォントかどうかは導入前に確認すること。本番運用では厳格モードのまま対象フォントを確実にインストールし、
`AllowFallback` は開発環境での動作確認用と位置づける(CLAUDE.md「開発コマンド」も参照)。
`FontResolver` を直接使い、`RegisterFontFile`・`RegisterFontDirectory` で後からフォントを登録した場合も、
それより前に解決済みのフォント名(代替フォントで解決したものを含む)に登録が反映される。ただし代替フォント名の書体は作る時点で確かめるため、
`FontFiles`・`FontDirectories` で登録すること(後から登録する書体を代替フォント名に指定すると、作る時点でエラーになる)。

### 日本語の人名・住所の文字(外字・異体字)

宛名・住所の文字は、次の仕組みで豆腐や別の字に化けないようにしている(要件11)。

| 項目 | 挙動 |
|---|---|
| 同梱フォント | BIZ UDPゴシック(JIS第1〜第4水準、IVSの一部。SIL OFL 1.1)をライブラリに同梱している。`AllowFallback()` の代替先(代替フォント名の省略時)はこのフォント。日本語フォントの無いサーバー・CIでも日本語を描画できる。セル書式で「BIZ UDPゴシック」を指定すれば厳格モードでもそのまま使える |
| 外字 | セルのフォントに字形が無い文字は、`GlyphFallbackFamilies`(既定: BIZ UDPゴシック → IPAmj明朝)の順に、字形を持つフォントでその文字だけを描く。送り幅もレイアウト計算に反映される |
| 異体字 | 「葛」+ U+E0100 のような異体字セレクタ(IVS/SVS)付きの文字は、その異体字を登録しているフォントの字形で描く。どのフォントにも登録が無ければ `MissingGlyphException`(基底文字で黙って代用しない) |
| 濁点 | 「か」+ U+3099(合成用濁点)は「が」の字形で描く。CJK互換漢字(「﨑」U+FA11 など)は正規化せず、渡されたコードポイントの字形で描く |
| フォント名 | 「ＭＳ Ｐゴシック」「游ゴシック」のような日本語のフォント名は、英語名(「MS PGothic」「Yu Gothic」)のフォントとしても探す |

「𠮷」(U+20BB7)のようなJIS第4水準の外の人名用漢字は同梱フォントに無い。これらを含む帳票を発行するサーバーには
**IPAmj明朝**(文字情報基盤のMJ文字、約6万字・IVS対応、IPAフォントライセンス)をインストールする。インストールされて
いれば既定で外字用に使う(Debian/Ubuntu は `apt-get install fonts-ipamj-mincho`、Windows は文字情報技術促進協議会の
配布ページから入手してインストールする)。IPAmj明朝は46MBあるが、PDFには使った字形だけを埋め込むため数KBしか増えない。
IPAmj明朝は明朝体のみのため、ゴシック体の宛名の中で外字だけが明朝体になる点に注意する。

社内で作成した外字フォント(私用領域 U+E000〜U+F8FF に字形を持つTrueTypeフォント。Windowsの EUDC.TTE など)を使う場合は、
フォントファイルを登録し、外字用の代替フォントに加える(EUDC.TTE も中身はTrueType形式だが、
Windowsの外字ファイルでの動作は開発環境では確認できていない。導入時に実ファイルで確認すること)。

```csharp
var fontOptions = FontResolverOptions.Strict with
{
    FontFiles = new Dictionary<string, string> { ["社内外字"] = @"C:\Fonts\EUDC.TTE" },
    GlyphFallbackFamilies = new[] { "社内外字", "BIZ UDPGothic", "IPAmjMincho" },
};
using var engine = Excel2PdfEngine.Create(fontOptions);   // または new Excel2PdfOptions { Fonts = fontOptions }
```

文字単位の代替は厳格モード(`FontResolverOptions.Strict`)でも行う。厳格モードが例外にするのは「セルのフォント自体が
見つからない」場合である。英字フォント(Arial・Calibri 等)のセルに日本語を入れた場合も、日本語の部分は
BIZ UDPゴシックで描かれる。Excel はこの場合ブックの東アジア用フォント(例: ＭＳ Ｐゴシック)を使うため、文字幅が違い、
折り返し位置などが変わりうる。日本語を入れるセルには、テンプレート側で日本語フォントを指定しておく。

`GlyphFallbackFamilies` を空にすると文字単位の代替を行わない(セルのフォントに字形の無い文字は `MissingGlyphException`)。
見つからないフォント名は飛ばす(IPAmj明朝の無い環境でも、既定の一覧のままでエラーにはならない)。

PDFから文字列をコピー・検索した場合、異体字の字形は基底文字(例「葛」)として取り出される(異体字セレクタは含まれない)。

### PDF出力オプション (`PdfRenderOptions`)

```csharp
// 既定: フォントを埋め込む(使った字形だけのサブセット)。PDF内の文字列検索・コピーが可能。
var withSearch = PdfRenderOptions.Default;

// 文字をアウトライン化する。見た目は同一で大幅に小さくなるが、PDF内検索・コピー・テキスト抽出は不可。
var compact = PdfRenderOptions.OutlineText;
```

`PdfRenderOptions` は `Title` / `Creator` / `Producer` / `RasterDpi` / `EncodingQuality` /
`TextRendering`(`PdfTextRendering.EmbedFont` / `Outline`)/ `MissingGlyphs` を持つレコード型。

`MissingGlyphs` は、セルのフォントにも外字用の代替フォントにも字形の無い文字を描画しようとしたときの扱い(要件5.5)。既定の
`MissingGlyphPolicy.Error` では、豆腐(□)や空白のままPDFを出力せず `MissingGlyphException` になる。
例外の `Text` に、その文字を含む描画文字列(1行分)が入る。代替フォントでの見た目確認など、
開発用途で欠落を許容したい場合だけ `MissingGlyphPolicy.Render` を指定する。例外メッセージには
描画文字列の先頭10文字だけが入る(宛名・住所がログに丸ごと出ないようにするため)。

```csharp
// 開発環境での動作確認用: 字形が無い文字があっても出力する(豆腐になる)
var lenient = PdfRenderOptions.Default with { MissingGlyphs = MissingGlyphPolicy.Render };
```

フォントは、帳票で使った字形だけを含むサブセットにして埋め込む(要件11.5。請求書サンプルで約54KB)。
CFF形式のフォント(Noto Sans CJK など)・可変フォント・埋め込み許可が制限されたフォントはサブセット化せず、
SkiaSharp が Type 3(字形の輪郭をそのまま収める形式。文字列検索がしにくく、異体字の文字列抽出も欠ける)または
フォント全体の埋め込みで出力する。帳票・外字用のフォントには TrueType 形式のもの(.ttf/.ttc。MSゴシック、
游ゴシック、BIZ UD、IPA系など)を使う。形式は拡張子では判別できない(.ttc にも CFF 形式のものがある)。

## 複数スレッドからの利用(ASP.NET Core などのサーバー)

ASP.NET Core のように、リクエストごとに別のスレッドで処理するサーバーで使う場合の決まり。

| クラス | 複数スレッドからの同時利用 | 使い方 |
|---|---|---|
| `Excel2PdfEngine` | **できる**(スレッドセーフ) | アプリケーション全体で1つ作り、すべてのリクエストで共有する。アプリケーションの終了時(実行中の変換が終わった後)に `Dispose` する |
| `Excel2Pdf` | **できない** | リクエスト(文書1件)ごとに作り、使い終わったら `Dispose` する。static フィールドやシングルトンに入れて共有しない |

- `Excel2PdfEngine` が複数スレッドで共有するのは、フォント(異体字の対応表を含む)とフォントの計量値のキャッシュ、
  プロセス内で共有する数値書式の解析結果のキャッシュだけで、いずれもスレッドセーフにしている。それ以外の状態
  (読み込んだブック・書き込んだ値・レイアウト・描画中のPDF)は変換の呼び出しごとに作られるため、同時に変換しても互いに混ざらない。
- `Excel2Pdf` は設定した値をインスタンスに溜めるため、1つのインスタンスを複数のリクエストで共有すると、別のリクエストの宛名・金額が
  混ざる。インスタンスを作るのは軽い(エンジンを渡せばフォントも読み込み直さない)ので、リクエストごとに作ればよい。
- 1つのエンジンを共有して同時に変換しても値が混ざらないことを、回帰テストで確かめている
  (`tests/Utsushi.Golden.Tests/Excel2PdfEngineTests.cs` の「共有したエンジンで同時に変換しても値が混ざらない」)。

### ASP.NET Core での例

.NET 5(Visual Studio 2019)の ASP.NET Core の書き方(`Startup` クラス)。パスはカレントディレクトリに依存しないよう、
コンテンツのルート(`IWebHostEnvironment.ContentRootPath`)から組み立てる。

```csharp
// Startup.cs: エンジンはシングルトンとして登録する。ファクトリで登録したインスタンスは、
// アプリケーションの終了時(実行中のリクエストが終わった後)に DI コンテナが Dispose する。
public void ConfigureServices(IServiceCollection services)
{
    services.AddControllers();
    services.AddSingleton(_ => Excel2PdfEngine.Create());
}

// コントローラー: Excel2Pdf はリクエストごとに作り、共有のエンジンを渡す
[HttpGet("invoice/{id}")]
public IActionResult Invoice(int id, [FromServices] Excel2PdfEngine engine)
{
    var order = _orders.Find(id);
    var template = Path.Combine(_env.ContentRootPath, "templates", "invoice.xlsx");

    using var pdf = new Excel2Pdf(template, engine, new Excel2PdfOptions { DocumentName = $"invoice-{id}" });
    pdf.SetText("A3", order.CustomerName)
       .SetText("F3", order.Number)
       .SetValue("C8", order.Total);

    return File(pdf.ToPdfBytes(), "application/pdf", $"invoice-{id}.pdf");
}
```

(`_env` は `Startup`・コントローラーのコンストラクタで受け取った `IWebHostEnvironment`。)

エンジンを渡さずに `new Excel2Pdf("...")` とリクエストごとに作っても正しく動くが、そのたびにフォントの読み込みをやり直すため遅くなる。
サーバーでは、上の例のようにエンジンを共有すること。

### 負荷についての注意

- 変換は同期処理で、1件あたり約0.1秒(開発環境で請求書サンプル1件。同一プロセスでエンジンを使い回した場合で、初回のフォント解決を除く。
  フォント埋め込み・サブセット化込み、Releaseビルド)CPUを使う。初回の変換はフォントの解決のぶん遅い。
  非同期版のメソッドは無い。同時に多数のリクエストが来ると、その数だけスレッドとCPUを使うため、同時に変換する数を
  `SemaphoreSlim` などで絞るか、キューに入れてバックグラウンドで変換することを検討する。
- 変換のたびに `.xlsx` の全体を読み直す(解析結果のキャッシュは無い)。テンプレートをバイト列で持つ場合
  (`new Excel2Pdf(bytes, …)`)も、内容の読み直し(解析)は毎回行う。

## `Utsushi.Core` の共通型

利用者が直接触れる可能性のある値型・列挙型(`src/Utsushi.Core/`):

| 型 | 内容 |
|---|---|
| `CellAddress` | A1形式のセル番地。`Parse` / `TryParse` を持つ readonly struct。 |
| `CellRange` | セル範囲(A1形式)。`Parse` / `TryParse` / `Contains` を持つ readonly struct。 |
| `UnsupportedElement` / `UnsupportedElementKind` | 未対応要素1件(種類・シート名・アンカーのセル番地・補足の情報・説明の文)。 |
| `FormatApproximation` / `FormatApproximationKind` | 書式の近似1件(種類・シート名・位置・補足の情報・説明の文)。 |
| `ArgbColor` | ARGB色。`Black` / `White` / `Transparent` 静的プロパティ、`TryParseHex`。 |
| `PointPt` / `RectPt` | ポイント単位の座標・矩形(原点は左上、Y軸下方向)。 |
| `Units` | pt / mm / px / EMU の換算ユーティリティ。内部座標系はすべてポイントに統一している。 |
| `ProcessingStage` | `UtsushiException.Stage` が取る値(`Parsing` / `Substitution` / `Layout` / `Rendering` 等)。 |

## 以前の版からの移行

帳票定義(`definition.json`)の仕組みを廃止し、入口を `Excel2Pdf` に一本化した(`.kiro/specs/excel2pdf-consolidation/`)。
以前の版から移行する場合は、次の点に注意する。

| 以前 | 現在 |
|---|---|
| `ReportPdfConverter`(公開API) | 削除した。`Excel2Pdf`、大量に発行する場合・サーバーでは `Excel2PdfEngine` を使う |
| 帳票コード・帳票定義のルートを渡す `Excel2Pdf` のコンストラクタ、`SetField`・`ClearField`・`ReportCode` | 削除した。置換キーの代わりにセル番地を指定して `SetText`・`SetValue` で書き込む |
| 帳票定義の `overflow`(`shrink`・`wrap`・`clip`) | テンプレートのセルの書式(「縮小して全体を表示する」「折り返して全体を表示する」)で表す。`clip` に相当する書式は無く、はみ出し表示になる |
| 帳票定義の必須キー(`required`) | 削除した。必要な値を書き込んだかどうかは呼び出し元で確かめる |
| `CheckFit()`・`FitCheckResult`・`FitIssue.SubstitutionKey` | `Check()` の `FitIssues`・`FitIssuesTruncated` を使う |
| 未対応の要素は黙って出力しない | **既定でエラー**(`UnsupportedWorkbookElementException`)。欠落を承知で変換する場合は `UnsupportedElements = Ignore` |
| `UtsushiException.ReportCode`・`PagedLayout.ReportCode` | `DocumentName` に改名した。`ToDiagnosticString()` の見出しも `document=` |
| `ProcessingStage.ReportDefinition`、帳票定義・置換キーの例外 | 削除した(`ReportDefinitionNotFoundException`・`ReportDefinitionSchemaException`・`ReportStructureMismatchException`・`SubstitutionKeyNotFoundException`・`RequiredSubstitutionValueMissingException`)。ほかの段階の整数値は変えていない |
| CLI の `--report`・`--input`・`--output`・`--definitions`・`--set`・`--override` | `check`・`convert` のコマンドと `--text`・`--number` などに作り直した(下記) |

既定がエラーに変わったため、移行の前に、使用中のテンプレートを CLI の `check`(または `Check()`)で確かめる。
未対応要素が見つかったテンプレートは、要素を取り除くか画像に置き換えるか、欠落を承知で `Ignore` を指定する。

## CLIでの利用例(参考実装)

`src/Utsushi.Cli/Program.cs` はこのライブラリの呼び出し例そのものであり、実装の参考になる。パスはコマンドの直後(オプションより前)に書く。

```bash
# 診断する(問題があれば終了コード1。書式の近似だけなら0)
dotnet run --project src/Utsushi.Cli -- check samples/reports/invoice/template.xlsx

# 変換する
dotnet run --project src/Utsushi.Cli -- \
  convert samples/reports/invoice/template.xlsx /tmp/invoice.pdf \
  --text A3="株式会社サンプル 御中" --text F3="INV-0001" --number C8=2153800
```

(開発環境にテンプレートのフォントが無い場合は、どちらの例にも `--allow-font-fallback` を付ける。CLAUDE.md「開発コマンド」参照)

| オプション | 対応するAPI |
|---|---|
| `--text <セル>=<文字列>` | `SetText`(複数指定可) |
| `--number <セル>=<数値>` | `SetValue(double)`(複数指定可。小数点は「.」。日時は Excel のシリアル値で指定する) |
| `--sheet <シート名>` | `Excel2PdfOptions.SheetName` |
| `--document-name <名前>` | `Excel2PdfOptions.DocumentName` |
| `--max-digit-width <px>` | `Excel2PdfOptions.MaxDigitWidthPx` |
| `--ignore-unsupported` | `Excel2PdfOptions.UnsupportedElements = Ignore`(`check` では、指定しても未対応要素を問題として数える) |
| `--allow-font-fallback [書体名]` | `FontResolverOptions.AllowFallback`(書体名を省略すると同梱のBIZ UDPゴシック。指定した書体が無ければ終了コード3) |
| `--allow-missing-glyphs` | `PdfRenderOptions.MissingGlyphs = MissingGlyphPolicy.Render` |
| `--outline-text` | `PdfRenderOptions.OutlineText` |

`check` は、未対応の要素・文字の収まらない箇所・フォントの代替・書式の近似(参考)を種類ごとに件数と1行ずつの説明で標準出力に出す。
文字の収まらない箇所は説明の文だけを出し、セルの文字列(個人情報を含みうる)は出さない。

| 終了コード | 意味 |
|---|---|
| 0 | `check`: 問題なし(書式の近似だけの場合を含む)。`convert`: 保存した。`--help`: 使い方を標準出力に出した |
| 1 | `check`: 問題(未対応要素・文字の収まらない箇所・フォントの代替)が1つ以上ある |
| 2 | 使い方エラー(コマンドが無い・不明、必須のパスが無い、値の形式が不正、値の代わりに次のオプションを書いた、同じセルを重複して指定した、`--text`・`--number` 以外のオプションを重ねて指定した、パスにNUL文字を含む)。理由と使い方を標準エラーに出す |
| 3 | 変換・診断のエラー(内部のエラーの `InvalidOperationException` を含む)。`UtsushiException` は `ToDiagnosticString()`(未対応要素による中止では要素の一覧を含む)を、入出力の例外はメッセージを標準エラーに出す |
